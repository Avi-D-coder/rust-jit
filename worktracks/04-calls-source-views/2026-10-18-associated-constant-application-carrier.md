Approved exact leaves: `frontend/member_index.rs`, `frontend/associated_constant_applications.rs` (new), `frontend/mod.rs` module declaration, and `frontend/entered_call_goals.rs` shared `written_argument` visibility only. `MemberIndex::associated_const_selection` is the existing candidate loop with a fixed-size AssociatedConstSelection outcome (declaration, provider impl, trait identity, provided-default flag). Existing public associated_const delegates and projects the same Digest, preserving old priority/ambiguity behavior. No parallel candidate selector or whole impl clone. Its old identity-only consumer route remains held until actual application consumers retain the structural result.

`associated_constant_applications::prepare_occurrence` consumes an existing entered Value goal's retained SourceLocalPlan, current source/environment, exact body/key/PathExpr node. It retains actual qualifier/member Rowan handles plus actual member context/edition, and all actual nested GenericArg AST handles in source preorder. It reuses the same entered_call_goals::written_argument for each actual argument, including canonical Type syntax sites and explicit pending source demands; Lifetime/Const/AssocType observations remain present with their genuine AST. Nested structure/parentage is the actual retained tree, not an inferred ordinal or flattened argument list. Only this path's descendants are visited once in cold preparation, not the entire file/body. Boxed fixed-size rows include AST handles and fixed-size site/BodyKey metadata; checked size arithmetic accounts private storage; retained source plan has an explicit root accessor for future query-retention accounting.

The result is deliberately named PathOccurrence, not an application certificate. Its semantic demand is always LexicalTypeAndSubstitution. It does no name/member/Type selection, no substitution, no initializer body preparation/execution and no cache lookup. It has no production consumer yet. A future owning pure query must retain it once with actual relevant lexical/Type/member dependency guards, resolve real qualifier Type and provider substitution, retain full canonical Type/Const/Region application, and connect ordinary initializer demand/packet/cache paths. Only then can identity-only associated_const consumers be removed. Currentness/source occurrence checks alone do not discharge those semantic dependencies.
