## Invariant and common representation

A module declaration binding occurrence has actual name spelling, namespace,
NameContextKey, owning edition, source occurrence, scope, visibility and selected
canonical declaration identity. Exact opaque item classes must not leak through
a context-free caller-root lookup. Lack of class comparability is not an unknown
macro producer. Shared namespace completion must distinguish genuine producer or
import demands from retained context-specific declaration facts.

Existing route: admitted GeneratedItems/actual pinned HygieneFacts -> retained
GeneratedHeaderPlan syntax/header occurrences -> NameNamespaces -> existing
MacroNamespaces direct/import/glob/private access algorithm -> sealed relevant
bucket/source/member/declaration proof. Ordinary original outlines and comparable
generated names currently enter the same root-class graph projection. That route
is to be extended, not replaced by an opaque-only direct-map resolver.

Proposed common kernel factoring: one BindingSet representation of definitions,
access, named reexports and pending rows. Each actual path retains root-class
BindingSet and keyed exact item-class BindingSets. Context-free adapters select
only root-class projection. Contextual lookup carries exact class with each goal
through the same lookup_from/glob worklist and selects the matching BindingSet.
Alias occurrence class and imported target occurrence class are separate facts;
name identity alone cannot supply either. Global glob edges also need the actual
binding occurrence class so root-class globs do not participate in opaque goals.

An opaque declaration receipt must be constructible only by actual source header
extraction from admitted GeneratedItems (and future equivalent original occurrence
adapter), containing actual canonical GeneratedItemKey, exact name span/range/raw
context/pinned item class/edition, scope/visibility, source selection/record
descriptor/epoch stamps. A public NameLookup, NameDefinition/TypeId/digest/pointer
is not authority to mint it. Context equality is pinned service output; no manual
mark stripping, guessed defining owner or source-name mapping.

Exact-context imported/reexport and generated module-prefix cases remain genuine
typed demands until binding/target occurrence and pinned adjustment receipts exist.
Absence is not asserted merely because only direct rows have been retained. Root
will consume real class-keyed bucket/source receipts in its existing pure query
framework once source representation and shared kernel are coherent. No private
side-cache, origin-specific evaluator or per-operation rebuild.
