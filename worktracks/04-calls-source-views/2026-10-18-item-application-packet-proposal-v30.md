The same `impl<T: Foo> Foo for Proxy<T> { const X: i32 = T::X; }` initializer must execute under different actual T arguments and yield different i32 values. ## Smallest complete source identity, separate from physical bindings

Retain an immutable selected application with (a) the actual selected constant declaration and current source/body/signature identity; (b) the selected provider impl, implemented trait and default/override distinction already returned by `AssociatedConstSelection`; (c) canonical ordered entries `(BoundKind, ParamKey, GenericArg)` for **exactly** the selected initializer signature's declared parameters; (d) actual Self/trait application evidence and the owning query/currentness guard. The parameter definition is the constant's definition, not the impl definition and not its caller's unrelated parameters. Namespace, ordinal, owner and GenericArg variant must agree with the real signature; no duplicate, missing or extra entries may constitute a completed application.

Use stable structural encoding of the complete Type/Const/Region arguments. `TyTerm`, `GenericArg`, `ConstTerm`, `RegionTerm` and `BoundKind` already have explicit stable encodings. An immutable sorted entries wrapper can reuse `traits::subst::Substitution` validation/application; the existing substitution map has no public canonical iterator/encoding, so a narrow shared immutable entries API is preferable to a second substitution implementation. No display text, TypeId, argument result type or full caller GenericEnv belongs in this identity. A source/body version or equivalent selected callable source certificate is needed because the item definition identity alone does not establish unchanged initializer contents.

Runtime Type descriptors form a separate paired table. For Type parameters, reuse the existing `ArgumentType { source, descriptor }` plus ordinary explicit-argument contract path. A descriptor cannot recover source Const/Region arguments. `GenericEnv`/`PreparedCallContracts` currently retain only Type substitutions; `SignatureSubstitution` creates inference variables only for `GenericKind::Type`. Full Const/Region **entry** needs a common packet/environment extension. Until then, a declaration requiring those bindings must remain explicitly pending; retaining an AST or filtering to Type entries must never mint a completed application. `ConstTerm::Value(u64)` cannot represent arbitrary signed/wide source constants: unsupported values need their representation prerequisite, never truncation.

A bounded first runtime slice may support declarations whose complete actual binder contains Type parameters only, using this full-kind identity carrier. This is an explicitly scoped Type-only execution component, not full Const/Region acceptance. Nested source argument kinds remain structurally retained; ordinary contract limitations such as `closed_term` rejecting nominal Const/Region applications remain named holds.

## Reuse genuine selected owner syntax and common substitution

Do not extend `source_types::impl_self_type`, `generated_impl_self_type` or `impl_owned_name`'s historical synthetic-header parsing. For the actual selected constant, the ordinary current `FunctionSignature`/`DefinitionSource`/`DeclarationContext` identify its genuine Const AST. Its immediate `AssocItemList -> Impl` parent supplies the real `self_ty()` and source generics; a Trait parent supplies the actual implicit Self and real trait parameters. Use the same actual-AST declaration Type walker with `WrittenTypeDeclaration::function_syntax` over the **constant signature and real declaration syntax**, so owner parameter ordinals are already rebased to the selected initializer definition. The relevant header/scope/edition/hygiene/cfg/epoch and generated-source proofs remain mandatory. Missing actual owner syntax remains pending, never a fabricated Impl/PathType.

For the Proxy witness, the real impl self Type lowers to `Proxy<Param(constant, T-ordinal)>`, and actual reached Self is the source term `Proxy<Abc>` from the caller's paired binding. The existing `SignatureSubstitution`/`Unifier` can relate that Type template to actual Self and obtain T=Abc. Convert only those actual selected-signature bindings to ordinary `ArgumentType` entries. Do not copy caller A/B wholesale. For a provided trait constant, bind the genuine selected signature Self ordinal and each actual trait argument from the selected trait application; a missing trait argument remains pending.

The VM unifier intentionally ignores region differences and treats some array const parameters permissively. That relation is useful for runtime Type admission but **cannot** derive or canonicalize full source application identity. Preserve original exact source arguments in the carrier before any relaxed runtime relation, and require a real complete source substitution for all non-Type kinds. No static borrow/type/privacy checks are added.

Carry that same handle through `InitializerDemand`, `CallResolver::initializer`, ordinary source call preparation, `CallContinuation::Initializer`, return, unwind and retry. The ordinary VM still executes the initializer body; no pure evaluator or alternate executor is involved. The common entry accepts a nonempty signature only when the checked application exactly covers it and supplies the paired ordinary runtime Type bindings. Otherwise keep the current explicit packet hold.

Use one immutable source application key for existing `const_cells`, `static_cells`, `static_views`, in-flight state and `(PC, application)` retry values. Root's existing evaluated-template/ordinary aggregate-copy behavior remains unchanged; application identity does not authorize different copy/drop behavior. Failures, cancellation and source invalidation must not install a half-initialized cache entry. Return/unwind must restore the same application rather than recomputing from the restored caller frame.
