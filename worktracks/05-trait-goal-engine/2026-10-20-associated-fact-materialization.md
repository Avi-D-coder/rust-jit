### What the pinned Impl query actually computes

Pinned `collect/clauses_of.rs:28-76` calls `explicit_clauses_of`, appends
`inferred_outlives_of`, then adds `Self: Trait` only for trait definitions.
For an actual Impl, `explicit_clauses_of` reaches
`gather_explicit_clauses_of` through its non-Trait/non-AnonConst branch
(lines 505-612). RPITIT/delegated-fn/opaque-only branches are not impl branches.
`generics_of.rs:202-205` gives ordinary Item nodes (including Impl) no generic
parent. `outlives/mod.rs:15-54` returns the actual `_ => &[]` result for Impl;
no ADT outlives-crate traversal is needed merely to supply an impl's own clauses.
This is distinct from Q89 `impl_super_outlives`, which the next solver demands
separately after matching an impl.

`gather_explicit_clauses_of` requires these actual inputs/effects, in order:

1. Retain the actual impl generics, typed self Type and optional identity trait
   reference. A default impl additionally inserts its real identity trait
   clause at the impl span (lines 169-176, 212-224). Ordinary non-default impls
   do not receive an unconditional Self:Trait clause.
2. For each own type parameter, run pinned implicit sizedness and default-trait
   policy with that parameter's actual inline/where bounds and source span
   (lines 230-254). The policy can produce Sized/MetaSized or no default according
   to exact roles, explicit relaxation and owning-crate configuration; it is
   not a spelling-based `T:Sized` fallback. For each const parameter, emit
   `ConstArgHasType(actual Const::Param, actual declared Type)` at its parameter
   span (lines 255-263). Lifetimes add no implicit clause in this loop.
3. Lower all inline/where predicates with Filter::All and actual binders
   (lines 268-270, 322-386). This includes trait/outlives clauses, actual
   associated equalities and associated bounds via common lowering. Empty
   `where Ty:` preserves WellFormed(Ty) when Ty is not a plain parameter
   (lines 337-355). `?Trait` remains default-relaxation metadata, not a negative
   requirement. Higher-ranked/qualified/negative syntax cannot be dropped.
4. Only when that impl's owning crate enables generic_const_exprs, collect
   ConstEvaluatable from the already lowered clauses plus actual impl self Type
   and optional trait reference (lines 272-274, 412-494). The pinned visitor
   deliberately skips const-parameter defaults until instantiated and direct
   type consts; it must retain genuine const kind/parent/span identity. Merely
   observing GCE off in the selected executable root does not certify a foreign
   impl's owning-crate branch.
5. `unstable_feature_bound` contributes UnstableFeature(feature-symbol) clauses
   with the actual attribute spans (lines 276-285). This is a clause input,
   distinct from compiler lint/privacy/stability diagnostics. The pinned parser
   is `rustc_attr_parsing/src/attributes/allow_unstable.rs:34-56`; its semantic
   symbol/span output can be adapted without adding its static target checks.
6. Deduplicate by the actual `(Clause, Span)` pair in insertion order using
   pinned FxIndexSet semantics, retaining identical clauses at distinct spans
   (lines 159-161, 287). Do not sort/deduplicate by source text or clause alone.
   Then run the pinned constrained-parameter ordering on actual TypeIR clauses
   and self/trait heads (lines 289-305). Finally retain GenericClauses with
   actual generics.parent and ordered clause/spans (line 318).

Pinned `constrained_generic_params.rs::parameters_for_impl`, `parameters_for`
and `setup_constraining_clauses` are source preparation, not another trait
solver. The ordering moves ready projection equalities before the bounds that
use their outputs, collects parameters through upstream TypeVisitor and treats
non-injective projections/const aliases correctly. It excludes projections from
the very implemented trait and expands free alias Types before constraining
parameter collection. Its fixed-point/permutation must be mechanically reused
from this pin; a new LRR specificity/toposort/projection-normalization algorithm
would be the wrong repair. A mechanical generic-Interner port needs a genuine
free-alias expansion/type query adapter where that input is demanded. The
ordinary source-Type resolver often already resolves free aliases, but that
must be established from actual encoded terms, not assumed for every input.

### Const effects are separate query families

Pinned `hir_ty_lowering/mod.rs:1055-1148` emits the ordinary Trait clause for
normal Filter::All bounds. An always-const positive bound additionally emits
HostEffect(Const). A `[const]`/Maybe bound does not add an unconditional effect
there: its ordinary trait requirement remains, and its conditional effect
belongs to `collect/clauses_of.rs::const_conditions` (lines 1053-1181).
For an actual conditionally-const Impl, that separate query traverses the actual
impl generics with Filter::ConstIfConst and has no inherited parent; it retains
poly trait refs/spans from Maybe HostEffect clauses. It cannot be certified by
stripping const modifiers or substituting an empty condition list.

Actual next-solver consumers confirm this boundary:
`solve/trait_goals.rs:60-119` and `solve/normalizes_to.rs:254-296` run their own
DeepReject, default/polarity checks, fresh args, probe and equality before
instantiating `clauses_of(impl)`. Effect goals additionally require constness
and then `const_conditions(impl)` (`solve/effect_goals.rs:136-196`). The source
adapter must retain every actual bucket member; only upstream may reject it
through these semantics. A missing clause producer is a preparation hold,
never permission to erase the candidate or manufacture NoSolution/empty facts.
