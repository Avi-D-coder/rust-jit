# Qualified associated calls: next common source identity join

The unchanged primary witness remains `tests/ui/macros/macro-as-fn-body.rs` (import SHA256 `6ae5e64fd603f1817e3e5a8b69c09b7b72cf39ab8ecc8d58df6706c3b9bf3797`). `Baz::bar()` needs the default `Foo::bar` identity and an actual `Baz: Foo` witness; `Qux::bar()` needs the inherent item on the source nominal Qux; `bar()` is a separate module declaration emitted by the same real macro. None may be selected from basename `bar`, concrete runtime descriptor or macro identity. This is a source review and next-task proposal, with no new runtime terminal.

The actual reached route is indexed CallExpr → Query44 `entered_call_goals::prepare` → Query39 `source_value_goals::prepare`. Its PathExpr branch returns `ValueGoalDemand::PathAdjustment` when the path has a qualifier. Query44 retains that result. `entered_module_callables::canonical_module_declaration` correctly requires a module scope with no owner; removing that check would incorrectly use module authority for an associated call. Keep that refusal until common member resolution supplies a selected identity. The normal interpreter/cleanup continuation must remain the eventual consumer; do not add another call evaluator.

Existing source infrastructure is substantial but narrower than the required member service. `SourceType` can prepare genuine selected nongeneric nominal schemas, and `Frame` already keeps TyTerm source views separately from descriptors on slots/parameters/returns. `traits::term` already supplies typed binders, ParamEnv, TraitRef and projection terms. `frontend/source_view.rs` admits a symbolic function predicate, but is not the complete M018 member-facing SourceView service. `qualified_type_names::prepare` consumes actual indexed Type occurrences and the ordinary hygienic resolver; associated-type tails remain explicit missing work. A Value-position PathExpr qualifier is not automatically an indexed Type occurrence, so do not manufacture a Type PcKey or reuse the final Value segment as a nominal Type proof.

The next useful bounded production slice is **canonical associated declaration preparation**, before candidate enumeration. It should return actual immutable associated declaration rows and source-owner joins, rather than an API that always returns NeedSymbolicSourceTypes/NeedImplCatalog.

1. Factor the existing AST outline kernel, preserving its public module-root behavior, to accept a privately authenticated associated root context. The private constructor must join the actual enclosing trait/impl AST declaration in its admitted parse to its unique real Outline row, header and source context. Original Outline already creates trait child `ScopeKey.owner = trait DefKey fingerprint`, impl child owner from its HeaderRecipe fingerprint, and corresponding associated DefKeys/HeaderRecipe.context/BodyHandles. Do not create a synthetic trait/impl wrapper or parse display text. The new scanner's source-entry identities are not canonical DefKeys. Its ScannedImpl.header_identity includes associated raw headers and has a different domain from the Outline owner HeaderRecipe fingerprint; equality between these identities is invalid.

2. For real generated TraitItems/ImplItems, use the already admitted `GeneratedDeclarations::admitted_parsed()` and its actual record, parent_inventory and parent_invocation chain. The scanner's Fragment row retains grammar/root lexical scope only. `producer.scope` alone does not supply canonical Trait/Impl owner: scanner lexical_context accounts modules and function owners, while the canonical enclosing owner must be joined from the real parent AST/Outline. Use completed declaration fragments and exact producer/range attachment, including replacements, current epoch/cfg/source and mixed token editions. Prepare a bounded parent/output index once per genuine completed subtree, borrowing retained Arcs; never rebuild it per selected member.

3. Factor existing pinned item header/name transport into a common retained-tree extraction kernel usable by Items and actual associated grammars. `declaration_output::DefinitionCapture` currently captures MacroRules only; it does not publish arbitrary function/member definitions. `GeneratedItems::admit` intentionally requires GrammarSlot::Items, and `GeneratedHeaderPlan::prepare_using` requires no root owner. Do not pass associated output through those APIs with a forged Items key or remove their owner checks. Reuse actual structural paths, header/source attachments, name span contexts and GeneratedItemKey construction from the common extraction code. Preserve existing Items identities; explicitly version any new associated-root representation. This kernel should not reparse, run a producer, lower a body or construct a world registry.

4. The resulting common canonical fact should retain borrowed/shared handles for actual DefKey, HeaderRecipe, DeclarationContext, admitted source/root/producer proof, optional cold BodyHandle, token name occurrence/edition/context and actual enclosing canonical trait/impl owner. A proposed private factory `PreparedAssociatedDeclarations::prepare(actual_completed_owner, actual_source_plan, db)` returns a usable immutable index keyed by canonical owner and source entry; its rows expose canonical facts, not selected methods or applicability. The arguments here name proof requirements, not permission for caller-selected hashes: construct owner proof only at real discovery/outline admission. Reuse existing DefinitionSource/DefinitionHeader/DeclarationContext input publication and namespace dependency framework where they fit, with one checked atomic coordinator publication. Factor common canonical source validation out of module-only admission where appropriate; keep module-only eligibility in its caller. New source artifact roots and accounting, if needed, remain root/DB-owned.

The acceptance controls for that slice are the same unchanged fixture across original, real user emission and wrapper contexts, plus LRR controls outside imports for wrong actual parent, changed record/source/cfg/epoch, repeated identical emitted names in different owner scopes, and a body edit preserving semantic header identity while invalidating the body locator. Compare actual canonical owner/DefKey/header/name context and ensure no FunctionSignature, BodyStructure or Thunk query while building the fact index. This establishes declaration preparation only; it does not count as full fixture or runtime compatibility.

After that source join, the ordered next services remain M017/M018 source-term and definition-context integration, M019 complete configured/facade ImplCatalog plus exact trait/self/binder/predicate lowering, M020–M024 canonical transactional goals/conditional selection/projections, M025 member identification and M026 dictionary/default-body fulfillment. Implement `ResolveMember` through the existing memo/provider framework with source view, definition ParamEnv, lexical trait imports, member syntax, owning token hygiene and relevant sealed headers. Retain blanket/conditional/negative candidates conservatively; a scope inventory is not catalog completeness. Only a selected canonical item/witness may feed Query44 and existing source-call admission. For Baz the default body executes with rigid trait Self under its definition context; it must not become an inherent Qux-like selection.

Ownership proposal: scanner/canonical-owner factor and new declaration-fact leaf can be a disjoint source worker; pinned adapter header extraction is a separately reserved factor; root owns SourceDiscovery/publication/DB accounting hooks; the Type worker owns qualified nominal-prefix/source-goal reuse; the member/trait worker owns M019–M026 after prerequisites. No files in these areas are changed by this review. The parent should assign one bounded factor at a time after observing current validation, preserving all tested frozen sources.

Reached member query keys bind actual source/scope/edition/epoch and relevant positive/negative bucket/catalog dependencies; guards replay immutable dependency versions without source walking. No full-world namespace census, per-phase parse, immutable BodyIndex clone or per-member completed-tree reconstruction is acceptable. Runtime, all-context matrix, effects/cleanup/suspension and scaling measurements remain unexecuted.
