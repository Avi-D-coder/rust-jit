## Final representation and atomicity review

Seven changed leaves: runtime/arena.rs (authorized narrow common lazy/atomic reservation APIs), runtime/reference.rs, runtime/cell.rs, runtime/cell_reference_return.rs, runtime/cell_reference_return_tests.rs (mechanical location access only), new runtime/str_storage.rs and str_storage_tests.rs. Old flattened location fields are removed; no parallel legacy lease executor survives. ReferenceLease::Location retains exact root/enclosing/final_cell/source-projection rows; BufferLease holds opaque ImmutableStrId + start/end. Existing final-cell/ancestor/selected-member return checks now first require the Location variant and otherwise preserve their exact logic. No buffer-return certificate is fabricated.

`GuestStore::immutable_str_ticket` / `immutable_str_range_ticket` are storage primitives, not VM op emission or source type proof. Input work is bounded by max run bytes before UTF-8 validation/hash. Content pool rows sort by digest and actual bytes; digest equality alone never establishes identity. Backings are immutable host-owned UTF-8 buffers (private String storage, with no guest FacadeType::String or ObjectId). They are rooted in the run store, not in a frame/cell lifetime. The reference remains kind9, shared Ref(target descriptor16), and standalone owning str/scalar APIs remain invalid. Range checks use str::get, enforcing start/end/order/bounds and UTF-8 boundaries without rescanning the entire already-validated backing. The read-only checked byte view is not equality, method selection or a slicing evaluator.

New content performs O(bytes) UTF-8 validation/hash/copy, O(log N) index comparisons (actual bytes checked on equal digest), O(N) sorted row insertion/growth, and arena capacity work. Pool reuse still validates/hashes input bytes before data lookup; this is not a performance-accepted installed literal path. The later source-certified VM literal integration must retain/select actual run storage handles rather than claim this byte-taking API proves zero repeated decoding or static literal hot-path performance. Checked buffer resolution is O(1) bounds/UTF-8-boundary/session/arena checks; it returns a safe borrow tied to GuestStore, never a persisted host pointer.

The combined publication admits every logical handle (new backing if needed, lease, ticket), owned UTF-8 capacity, sorted-index growth, reference/ticket/backing arena replacement capacities before publishing any guest entry. `GuestArena::new_lazy` defers/charges even sentinel buffers. `atomic_reservation_bytes` includes old/new transient capacity; `reserve_atomic` stages replacement buffers and actual capacity admission before moving any record, then charges net retained growth. Index replacement uses the same temporary peak rule. Final logical handle/text credit is rechecked after actual reservation. Subsequent allocation uses already-reserved capacity with no intervening guest callback or mutation; source/owner data remain immutable. Capacity-only successful reservations may stay charged after a later refusal; backing/index/lease/ticket entries do not publish a prefix on refusal. Legacy GuestArena::new sentinel accounting and old reserve callers remain named debt, not silently fixed or claimed accepted here.

ImmutableStrId carries actual store session plus generational backing handle. Wrong epoch/index/zero/retired or foreign same-epoch store backing is rejected. The buffer has no mutation/version API; moving/copying/dropping its shared reference value cannot invalidate its immutable run root. Run destruction/new-epoch storage invalidates old handles. Future String::as_str needs actual object/buffer owner/version and mutation invalidation joins; this component does not infer them from layout or a String ticket. Buffer mutation, target alteration and nonboundary ranges are rejected on checked lease use. Public storage allocation cannot mint symbolic Str, a static source region, a reference-call proof, a member or a recipe.
