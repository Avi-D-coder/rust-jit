# T054 actual array-length local context — uncompiled successor

This three-leaf successor follows the eight-path constant-local proposal (patch c93ea265). Two private production/source-adapter leaves change and one test child is added. Before hashes belong to that proposal, not directly to MAIN or canonical v68. Six new controls are uncompiled, as are the predecessor's30 controls. No canonical source, Cargo target or validation process was changed.

Local inference formerly stopped only at a const/const-fn/closure boundary. An actual let inside a repeat count in ordinary main, or inside a source array type, therefore acquired no legitimate context. The graph now recognizes only the closest actual ArrayType/ArrayExpr length containing the demanded statement, then replays the existing ConstantSource::array_length admission. That admission retains exact source/owner/cfg/attributes, generic/closure restrictions, parameter independence and preceding-local exclusions. Its actual length supplies usize result context to a fresh graph; unrelated locals still default independently and outer runtime bindings are not imported. Reached operations still enforce their own types/effects. This adds no function execution, type-alias query, storage, callable, macro or native permission.

A bounded provenance check compares retained immutable green roots because pinned ra_ap_syntax0.0.356 Parse::tree constructs fresh red roots. Direct red-node equality would reject genuine selections. Green identity is used only as an ephemeral ownership check, never serialized or used as a persistent query/cache key; range and exact selected green length remain checked. The pinned ra_ap_syntax and rowan0.17 source APIs were inspected before this correction. New negative controls use different actual foreign source bytes rather than a caller-supplied type/completeness flag.

The existing length helper performs a structural source-index scan. This successor precharges source width, actual syntax/token visits and conservative transient metadata before replay. It does not typecheck or execute cold bodies. Consequently length lookup's work can depend on the captured source index; the independent ordinary-const control for a cold local item body is unchanged. Work/metadata exhaustion remains a typed error. These charges are conservative logical accounting, not a measured CPU or physical-allocation claim.
