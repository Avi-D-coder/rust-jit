# Source-selected str byte views

T061/T062 follow the unchanged rustc `tests/ui/lexer/lexer-crlf-line-endings-string-literal-doc-comment.rs` and `tests/ui/array-slice-vec/estr-slice.rs`. They require `str::as_bytes` to expose the evaluated string's UTF-8 bytes as a shared slice. The pinned core member returns a shared view; the interpreter issues a slice lease over the same immutable root instead of copying bytes, decoding again or loading native std symbols.

The source-selected string method descriptor now distinguishes `len` and `as_bytes` by exact signature, body and member identities. The canonical standard compiler facet publishes both; macro-only/manual catalogues and wrong profiles cannot acquire them. The retained admission also captures the receiver's complete source term, including its region. A changed source region, mutable receiver or incompatible result source cannot reuse a prior member receipt. The VM preserves the receiver's region in the result `&[u8]`; a static physical backing does not create a stronger source lifetime.

The physical plan binds store session, epoch, exact source stamp/value, immutable root, UTF-8 membership, descriptor predictions and the cached slice lease. Commit reproduces a current descriptor batch, reserves destination/lease/ticket capacity and uses the existing atomic two-key slice descriptor commit. It issues one transfer ticket and caches one shared slice lease per root; later invocations reuse that lease. No backing object or element cells are copied. Byte-only storage does not acquire UTF-8 authority. Foreign, reset, stale-descriptor and already-issued plans fail before logical publication; quota refusal has no guest effects.

LRIR schema 16 appends opcode 46; existing opcode identities stay fixed and tag 42 remains reserved. Recipe domain advances to `lrr/v16/lrir-recipe`; the string method facet becomes `lrr/v2/str-method-facet`, retaining explicit signature/body/member encodings. Wire controls pin both string opcodes, prior-schema separation and alias/unknown-slot/duplicate-result refusal. Existing schema and opcode-count assertions migrate together.

Five new pending controls cover the eight original string initializer payloads across all editions with root/cache reuse, physical plan/resource refusals, and the actual unchanged CRLF execution prefix through the `as_bytes` operand. That prefix requires three preceding real assertions, current source admission, one opcode/result publication and unchanged receiver value. Negative controls cover mutable/changed-region/wrong-result source and exhausted fuel. Existing member/catalogue/wire controls are extended. The source prefix stops before later `include_str`/`contains`; whole-fixture acceptance is still outstanding. Physical setup controls alone are not source-member or full-fixture passes.

Exact predecessor hashes, no-fuzz/no-offset replay and Rust 1.99 leaf formatting passed. All compilation, runtime controls, whole original programs and the integrated milestone remain pending. Preserve the V88 range harness repair when assembling. Owned-string/general borrowed-storage views, indexing, `contains`, character iteration and other required runtime operations remain blockers; no task, interpreter acceptance, full-suite or JIT completion is claimed.
