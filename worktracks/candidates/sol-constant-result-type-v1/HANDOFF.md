## Exact root API and pre-fetch attachment

`CurrentConstantResultType::capture_current(db, source, admission: ConstantSourceAdmission, byte_limit) -> Result<Self, Diagnostic>` consumes the actual privately minted current source packet. It reserves checked retained metadata before revalidation/header extraction, never accepts caller-built ConstType or descriptor/length authority. `revalidate(db,source)` replays admission plus actual header result shape/role and checks every private proof field.

`check_current_expected(db,source,&ConstantWireType) -> ReadyScalar(&SourceScalarExpected) | RequiredArrayLength(&CurrentArrayLengthDemand)` revalidates first. Exact scalar or scalar/array-kind/primitive-element mismatch returns LRR-E-CONST-TYPE before provider/evaluator/initializer/callee work. Matching scalar returns an opaque source expectation; matching array never trusts or resolves the caller's count. `scalar()`, `array()`, `identity()`, `metadata_bytes()` and `admission()` are read-only accessors. The packet consumes admission to avoid unchecked BTreeMap/source-stamp clones.

In root public capture-and-fetch: capture current source/header packet, consume it into result readiness, call check_current_expected **before fetch/memo/provider entry and initializer/macro operand interpretation**. ReadyScalar can use its wire_type() and the packet's admission() for current fetch. RequiredArrayLength must resolve its exact source-owned demand through root's current typed length query, match the proven usize result against the expected array count, then enter the initializer. No query/evaluation is performed here. Existing borrowed fetch_current_constant(&admission) needs root's checked aggregate reservation before admission.clone(), or an owned helper; this packet retains the ownership API root requested.

SourceScalarExpected has only private primitive + source binding; primitive()/wire_type()/source_identity() expose data. The scalar exposed as array element is an **element expectation**, not top-level scalar readiness: root's enclosing check rejects Scalar expected for Array. Consumers must retain and revalidate the enclosing packet, not elevate a detached wire/primitive/digest into authority.

CurrentArrayLengthDemand privately retains exact SourceSelection, owning definition, DeclarationContext, BodyHandle including actual range, exact type-length expression range, parent plan identity (including concrete const-call arguments), and source binding. Getters source()/definition()/context()/body()/range()/parent_plan_identity()/identity(), expected_wire() (intrinsic Usize role) and request() (ArrayLength exact range) provide query data only. A header type length may lie before the narrower initializer BodyHandle.range; it is checked inside the actual owning declaration range, not fabricated as a body instruction PC. The parent's typed query bridge must independently admit and evaluate this exact source request. A demand carries no concrete length and cannot grant evaluation of an arbitrary range.

## Precise prerequisites

Current evaluator ConstType supports primitive scalar or a primitive array element plus expression. TypeAlias/import/qualified/associated/projection/generic/nominal normalization, nested arrays, references/strings and 128-bit live types are not broadened into primitives. Their existing exact source/effect diagnostics remain prerequisites. Scalar array-length role uses language Usize independently of a source alias named usize; it grants no value/length inference.

A const fn array return preserves its real arguments and exact signature length demand. The existing anonymous-length planner rejects fn parameter namespaces, even if that signature's written length is literal; the demand deliberately retains this missing context integration and does not relax it. Complete source/library/generated/native/foreign/ordinary-module currentness requirements inherited from current source admission remain prerequisites. A SourceScalarExpected, wire shape, TypeId or digest alone is not a descriptor/publication admission proof. The separate worker owns selected descriptor/published result joining.
