# Source-selected immutable string equality

Source-only T041/T062/M017 extension for the actual pinned `core::str::traits` PartialEq implementation: strings compare their UTF-8 bytes. The compiler facet selects two shared `TyTerm::Str` operands; string versus byte-array/slice source families are rejected in either direction. The facet and selected-instance digest domains advance to v2 so existing byte-only receipts cannot silently become string authority. The existing byte-oriented internal API names remain for the shared immutable comparison machinery.

Each string operand must retain a genuine committed UTF-8 reference and private immutable root membership before physical comparison. The bounded cursor still binds store/session, epoch, cells and value/root identities; it charges each compared pair, polls cancellation, and publishes one boolean only after completion. No pointer-equality shortcut or UTF-8 reinterpretation grants source authority. Byte-array/slice behavior and its ownership controls remain required regressions.

The new whole-main witness is unchanged rustc `tests/ui/lexer/underscores-in-unicode-escapes.rs`, additively imported with original licenses. It must execute both character and string assertions in every edition. The existing source-facet matrix now also covers str and mixed-family refusals. No new runtime/full-fixture pass is claimed: these five leaves are uncompiled and unexecuted, held behind the byte milestone and prior string packets. String methods, owned String, general mutable views and annotations/aliases remain outstanding.
