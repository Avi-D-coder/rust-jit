## Violated invariant and actual source evidence

The absence of a published Drop row is not evidence that an actual configured Rust program has no Drop implementation. A non-local impl inside an unentered function is semantically active. Current `MemberIndex::build` consumes module `Outline.items`; `CompletedSourceEnvironment::member_index` adds generated units/associated outputs, while `Database::publish_local_containers` only adds body-owned `LocalContainer` rows after `PreparedSourceLocalPlan` preparation. Therefore first-use runtime inventories omit valid cold local impls. A later append to the same live handle cannot undo already executed no-Drop transfers.

Minimal LRR correctness witness, not an upstream acceptance claim: module `struct D; const C:D=D;`, uncalled `fn never(){ impl Drop for D { fn drop(&mut self){ /* increment actual static counter */ } } }`, and reached `main` which creates/drops `C` and asserts the counter. All ordinary/macro/wrapper/std-macro contexts must use the same declaration Type/name/member service; the enclosing function must retain no executable body preparation. This is declaration discovery, not whole-program static checking.

Primary unchanged already-imported runtime witness: `fixtures/upstream/rustc-checkout/tests/ui/zero-sized/zero-size-type-destructors.rs`, `//@ run-pass`, owning 2015 default, no auxiliary. `foo` declares a local Foo/Drop, constructs `[Foo,Foo,Foo]`, and main asserts the actual mutable static destruction counter reaches zero. Complement: `tests/ui/drop-bounds/drop-bounds-impl-drop.rs` returns a real body-local Drop type. Neither original tests the unentered-function/global-type absence counterexample; the LRR cold-declaration control must establish that extra contract separately. No imported original is edited. Existing imported Drop tests are not new passes or a complete Drop suite.

## Existing services to extend, and limits that must remain explicit

1. `ParsedFile::scan_declarations_in_scope` already traverses cfg-active declaration syntax throughout functions/blocks. `ScannedImpl` retains exact parse/path/cfg/origin, range/header/header identity, associated headers, lexical function scope and container ranges. `SourceDiscovery` owns actual `ScanNestedDeclarations` macro/attribute jobs, replacements and generated child/trait/impl frontiers. No second parser is needed.
2. `SourceDiscovery::impl_header_inventory` merges original scan Arcs, intrinsic argument scans and completed declaration/argument fragments, then applies `exclude_replaced_sources` and `exclude_generated_replacements`. `Database::publish_discovery` validates every scan against actual sources or completed facets. Preserve all these ownership checks; a retired raw row must not be revived.
3. `QueryKey::ScopeDeclarationInventory` depends on the genuine `DiscoverySeal`. `traits::index::PreparedScopeImplHeaders::prepare` retains that current inventory and checked locators back to exact `DeclarationScan`/`ScannedImpl`; `traits::header::SourceImplHeader` is the existing input adapter. Reuse it, rather than constructing a second global raw-header index.
4. `PreparedOriginalAssociatedDeclarations` already joins module rows to canonical headers and deliberately represents cold local owners as `canonical=None` / `NeedCanonicalOwner`. That missing canonical attachment must remain pending until an actual shared declaration service produces it. Raw scan identity is NOT a canonical DefKey: `declaration_scan::lexical_context` uses declaration-function-owner source digests, whereas `BodyItemBudget::collect` uses genuine parent DefKey + lexical ordinal + header. Renaming or casting one into the other would be a source identity bug.
5. `syntax::body_items::BodyItemBudget::collect` and `entered_macros::collect_container_members` are the existing canonical local item/member producers. They store actual headers and body handles without lowering executable code. However `ParsedFile::lexical_facts` currently interleaves their scope census with local-pattern/binding capture. Calling `entered_macro_facts`, building a `BodyIndex`, or publishing `BodyEnvironment` for every cold function would violate lazy preparation and may reject unrelated cold patterns. The declaration/scope subset needs to be factored and shared, not copied wholesale or called under a fake entry.
6. `DeclarationFieldTypes`/`HeaderTypeSite`, `PreparedSourceLocalPlan::resolve_header_target`, `lookup_prepared_field_type_prefix` and common module/source namespace queries already resolve actual impl header Type names with lexical imports, shadowing, generic binders, token context and edition. Their current owner is an entered plan. Extract the immutable declaration scope/Type occurrence roots needed by that same service; do not use module lookup alone when local shadowing is possible, fabricate a function signature, or parse header display text.

## Proposed bounded interfaces and implementation order

First producer component: an immutable declaration-only scope/header plan in a new syntax helper, factored from the existing canonical collector. Inputs are genuine retained `ParsedFile` plus actual parent declaration/BodyHandle metadata, cfg, header context and admitted generated occurrence ownership. It records the same lexical scope ordinals and canonical `BodyItem`/associated identities that the entered route later consumes. It does not collect executable local binding patterns, make source constraints, lower/verify thunks, or mint body-entry permission. The existing entered lexical route must consume/share the factored declarations rather than remain a parallel identity producer. Scope census branches for blocks, closures, match arms and let-chain scopes must be common; cold unsupported executable shape cannot fail the declaration plan merely because it is unentered.

Next shared source-header component: accept only a checked `SourceImplHeader` plus the retained canonical declaration-scope plan. Match actual source parse/cfg/epoch, impl range/header, enclosing canonical declaration, local scope and associated member identities. Retain actual AST Type occurrences with their token NameContext/edition. Extend the existing header prefix/resolution service over that immutable scope root; resolve self/trait and true generic arguments/bounds through common symbolic Type/member machinery. A typed outcome distinguishes `Resolved(common LocalContainer/impl requirements)` from `Pending(real header/producer/owner/type reason)`. A present unresolved header is never silently omitted or classified as not Drop. Generic/alias/qualified/incomplete applications stay explicit until the same common source resolver supports them.

Transport component: retain the actual scope-header inventory Arc/closure dependencies in `CompletedSourceEnvironment`, with the common prepared canonical/header results derived cold once (memoized per real source/cfg/edition/epoch). Add resolved rows through the existing `MemberIndex::publish_local`/canonical identity layer and carry unresolved scope/producer evidence separately. Entry must deduplicate the same canonical identities; it must not create a second set when the body is later reached. `CompletedSourceEnvironment::member_index` is currently synchronous and has no Database: do not smuggle query side effects into it. The coordinator must perform query-backed header preparation before retaining/installing a completed result, or add an explicit cold preparation method while the existing sync getter remains a retained-result getter.

This transport is a positive-header/member prerequisite, not an absence certificate. The existing `SealDomain::Scope`, raw pending-producer lists and `PreparedScopeImplHeaders` explicitly do not certify whole configured-world impl completeness. Source/auxiliary/dependency/facade/module/attribute/include/generated producers which can contribute impls must be covered by a real configured graph/producer closure; unavailable closure, unresolved header applicability, or missing generated attachment remains pending/unknown. No new `NoDropProof` may be based on a published-only set. Parent retains owned nominal template refusal meanwhile.

## Common trait goal engine boundary

Current checkout has no tabled trait goal engine to reuse: `traits/mod.rs` explicitly says it is implemented later; actual modules are term/unify/subst/pointer_terms/header/index. There is no `TraitGoal`, `GoalResult`, or negative impl-completeness query. `MemberIndex::implements_depth` and `associated_types::normalize` are existing limited published-row consumers, not sealed negative goals. Do not create a Drop-specific solver or a second global resolved set. The source header/canonical plan above should feed the specified common engine when implemented. A future requested `Drop(TyTerm)` goal must retain full symbolic application and relevant positive/negative producer/header dependencies; a no-solution result is admissible only with that genuine completeness proof. Runtime consumers retain its immutable proof/guard, rather than walking all source headers per copy step.
