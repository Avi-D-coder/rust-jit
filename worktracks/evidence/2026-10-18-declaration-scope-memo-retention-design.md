# Declaration scope plan memo-to-entry retention design

Read-only successor design under standing V32 source freeze. Owner `/root/generic_projection_resume`; no Rust changes/Cargo. Current plan source hashes: entered_macros d755cf03, declaration_scope_plan15baa9b9, syntax/mod09fc9c46. This does not authorize negative impl completeness or perform source/member publication.

## Shared immutable representation

The narrow representation is one immutable payload Arc, not eight field Arcs. Introduce `DeclarationFacts` containing current nonbinding vectors items/members/imports/invocations/scopes/events/opaque. `DeclarationScopePlan` retains `Arc<DeclarationFacts>` and immutable ordered binding requests, plus the existing real parse/body/scope/cfg identity. `EnteredMacroFacts` retains an owned binding-recipe Vec plus the same Arc; read-only accessors or `Deref<Target=DeclarationFacts>` preserve the existing readers. Never provide DerefMut or Arc::make_mut: those would silently deep-copy headers after sharing.

The single lexical_declarations walker builds owned DeclarationFacts and freezes it once. A plan method `prepare_entered(&self)` performs the same ordered BindingBudget apply, returning EnteredMacroFacts with only new binding recipes and Arc::clone of declaration facts. The existing fresh `into_entered` becomes a thin consuming wrapper if compatibility requires it; it does not clone immutable rows. A cold header consumer and every later entered source context retain the same payload allocation for the same real syntax version. Actual source/epoch replacement legitimately selects a different memo/plan; no equality-by-display reuse.

Exact nonbinding mutation census: syntax/entered_macros.rs is the canonical collection owner; outside it only frontend/body_namespace.rs::Namespace::capture constructs the other EnteredMacroFacts literal and pushes/remaps nonbinding rows for a composed ancestor namespace. That function should compose an owned DeclarationFacts builder and freeze it at return; its deliberate scope-remapped derived view remains a distinct product. It must not mutate or clone the shared source plan to add binding recipes. Existing entry readers, including PreparedBodyContext::facts, local declaration/member publication, source_locals, import/macro occurrence capture and metadata iterators read the shared payload. Existing EnteredMacroFacts Clone becomes cheap for nonbinding payloads; its mutable binding-recipe Vec remains per prepared context as today. Frames continue owning runtime binding state, not syntax facts.

## Exact memo and source ownership

A proposed pure `QueryKey::DeclarationScopePlan(BodyKey)` consumes actual DefinitionBody(definition), DefinitionSource(definition), DeclarationContext(definition), CrateCfg(real context crate), DefinitionHeader if needed for context, and ParseFile(actual locator). It verifies exact BodyKey/body handle/range/profile and context owner using the same real published inputs as declaration signature services. The provider invokes only the shared pure syntax collector. QueryValue retains an Arc<DeclarationScopePlan>; the memo already pins its ParseFile/input dependencies. It must not fetch DefinitionBody's BodyStructure, BodyEnvironment, SourceLocalPlan, Thunk or executable patterns merely to obtain metadata. Key additions require existing explicit stable enum tag, serde/exhaustive adapter joins, and no new resource-accounting census.

Original textual declarations are admitted by actual published source locator and ParseFile. Retained/generated declarations must read the real current RetainedSyntax input/actual generated record context rather than fabricate a global source or assume textual offsets match. Existing `RetainedSyntaxInput::require_current`, `Database::{retained_original_declaration,retained_generated_declaration}` and RetainedSourceLease retain actual publication. However those declaration projection helpers currently enforce already-published exact rows. A cold local canonical owner not yet published remains typed pending; the memo cannot invent those rows or turn the source-only DeclarationScan identity into a DefKey. This is the remaining producer/canonical header join, not an excuse to demand an executable environment.

PreparedBodySyntax is a nearby ownership pattern, not a substitute entry proof: its coordinator publishes actual CompletedSourceSyntax, the pure provider consumes that input, and RetainedSyntaxInput admission retains actual source/epoch/seal. Its `PreparedBodySyntax::construct` may assemble selected body syntax, so a cold header goal may consume only genuinely admitted declaration producer outputs as required, never trigger arbitrary executable/body lowering. A new source lease should not be manufactured from an Arc. Actual source closure missing => pending.

Preparation returns the plan together with its existing memo input guard (PreparedInputGuard from successful memo) and real retained source lease if relevant. Arc ownership proves allocation lifetime only; it does not prove currentness, namespace selection or call admission. Cold header composition captures relevant query dependencies in its pure parent. Runtime installed operations keep existing prepared guard checks; they do not fetch this query or rerun the lexical walker. Actual relevant publication invalidates; unrelated namespace additions do not enter this syntax-only memo's key/dependencies.

## Production consumer migration

Main common integration point: frontend/source_body_context.rs::AdmittedBodyContext::prepare_with_boundary currently calls parsed.entered_macro_facts at1608, then creates PreparedBodyContext{facts:Arc::new(facts)}. After real source admission/currentness and retained source lease establishment, fetch the plan memo for that exact admitted body, verify actual parser/body/context/cfg identity, and call prepare_entered on the retained plan. Retain the plan in PreparedBodyContext or rely on the shared facts/request owner plus memo pin; the plan must not be reconstructed for each name/Type/macro phase. Existing PreparedBodyContext::source / retained_lease / macro_outers / macro_hygiene / macro_ancestry remain genuine owners. No fake AdmittedBodyContext or BodyEnvironment is needed for the cold reader.

Database::prepare_source_local_plan continues its genuine coordinator publication and source member flow; it consumes PreparedBodyContext facts and requires no second lexical scan. The cold canonical/header join can borrow the same plan before that later body preparation. Retained declaration inputs can be registered without executable preparation only through their existing coordinator paths.

Direct adapter census that must remain named: source/changes.rs::{entered_macro_facts,retained_body_facts,entered_container_facts}; frontend/source_macros.rs legacy view.entered_macro_facts call; syntax/lexical_numeric_callees.rs::lexical numeric route; source_body_context main path; test-only source adapters. Pure ParsedFile has no Database, so its standalone entered method can remain a fresh syntax helper for tests/direct callers, but production consumers that already own a genuine plan must accept/borrow it instead of rerunning it. Container entry needs its actual ContainerHandle/header-context key and retained parent; do not coerce a container into an ordinary global function BodyKey. This is a separate exact key variant/join if demanded. None of these remaining adapters may be silently declared migrated from the main path alone.

## Bounded implementation order and acceptance holds

First representation slice: syntax/entered_macros.rs, declaration_scope_plan.rs and frontend/body_namespace.rs exact builder/adoption only; all existing syntax/namespace tests must preserve canonical metadata and binding request order. Then exact query key/value/provider + actual source admission consumer join, coordinating source_body_context and DB adapter owners. Do not patch broad runtime/memberIndex/associated applications. A third slice may join checked ScannedImpl -> canonical header/Type names once real parent headers are available. Complete configured-world producer closure and the common tabled trait/negative goal engine remain separate prerequisites.

Required control reuses unchanged zero-size-type-destructors original: cold query once and later normal entry retain the same declaration allocation (Arc identity), entry bindings absent before entry and present in original order afterward; memo repeated demand preserves handle; no BodyStructure/BodyEnvironment/Thunk/SourceLocalPlan before reached execution; relevant actual source/cfg/epoch changes reprepare and stale guard refuses; unrelated namespace changes preserve syntax memo. Actual handwritten/generated/wrapper/cold owner matrices and local shadowing/header Type resolution remain unexecuted until their relevant joins exist. No counter/fuel/cap/memory admission system is added. Full all8 review and exact hashes are needed for each actual source candidate; this design is no implementation or acceptance claim.
