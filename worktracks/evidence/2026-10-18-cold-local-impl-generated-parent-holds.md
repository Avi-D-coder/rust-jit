# Actual declaration owner versus generated caller — source review

Corrected canonical attachment source: associated_declarations44a25344 / declaration_impl_owners8b66a499 / tests99833ac2. No new Rust edits.

A generated caller invoking an original function does not change that function's declaration owner, impl header names, ScopeKey, actual BodyHandle or canonical local DefKeys. LocalImplOwners selects the actual captured declaration parent from ScannedImpl.containers and current captured Outline metadata, then the same lexical declaration plan. It never consumes caller locals/source and must not resolve an impl header relative to its caller. Thus original declarations have no new generated-caller exclusion.

The genuinely missing cases are distinct source producers. If a macro emits the impl inside an original function, the original DeclarationScan sees a real macro producer; the impl lives in the actual admitted GeneratedDeclarations scan/CompletedDeclarationFragment, not original source bytes. Its canonical attachment needs the actual output record/parent inventory/epoch plus the original function's retained declaration insertion context and same canonical scope plan. It cannot be obtained by searching original Outline ranges or fabricating a PreparedSourceView of flattened display text.

If a macro emits the function whose body contains a written impl, the parent canonical function belongs to the real GeneratedSyntaxInput or RetainedSyntaxInput and its published DefinitionSource/Header/Body/DeclarationContext. It is absent from the original captured source Outline. A generated body/associated boundary and retained declaration lease must establish that actual parent, then the same declaration scope collector can produce local rows. PreparedGeneratedAssociatedDeclarations already joins actual issued associated output chains to genuine parents; it does not by itself grant arbitrary generated-body impl ownership.

If the parent was replayed into retained syntax, current RetainedSyntaxInput identity/range/body mapping and actual source/epoch/seal are required. Raw original offsets/scan-function-owner digests are not canonical parent keys. Existing PreparedOriginalAssociatedDeclarations::NeedGeneratedParent is the existing explicit missing-parent outcome; no new blanket original-only guard was added. Cold nested local functions/methods lacking their own actual parent plan and opaque transformed owners similarly remain pending, never absent. No generated compatibility, member/trait applicability or global Drop absence closure follows from this metadata component.
