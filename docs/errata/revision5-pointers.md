# E-R5-008 — Raw pointers and function pointers

October 17, 2026. Implementation record (not a spec contradiction) for `*const T`, `*mut T` and `fn(A) -> R` under the simple-interpreter scope (E-R5-006: looser than rustc, no resource accounting; E-R5-005: one pipeline).

## Witnesses (unchanged upstream, `fixtures/upstream/rustc-checkout/tests/ui`)

`cast/cast-not-treated-as-lvalue.rs` (`&a as *const i32`, pointer `assert_ne!`), `cast/negative-integer-cast-to-pointer.rs` (`!0usize as *const ()`, `(i8) as *const ()`), `cast/as-cast-unifies-raw-pointer-and-fn-type.rs` (`&() as *const _`, `test as fn(i32)`), `consts/const-extern-function.rs` (`static f: extern "C" fn() = foopy`, struct field of fn-pointer type, `==`), `function-pointer/function-pointer-comparison-54696.rs`, `abi/nullable-pointer-ffi-compat.rs`. About 74 v13 inventory cases stop at `cast to ... requires its pointer, function-pointer or reference cast integration` (36, the cast target is a `*const`/`*mut`/`fn` type) or `local type requires later symbolic type resolution` (38, a `let` annotation of such a type). Classification of the 36 cast cases by target type: raw pointer 23 (`*const _`, `*const isize`, `*const ()`, `*const dyn Trait`, `*const [isize]`, `*mut U16`), fn pointer 11 (`fn()`, `extern "C" fn()`, `for<'a> fn(&'a ())`), plain reference 2 (`as &[u8; 1]`, `as &str`: a reference-to-array/`str` annotation, which takes the existing cast-coercion route once the shape check admits it). The 38 `let`-annotation cases are classified by their written shape while implementing step 3 below.

## Value and type representation

- **Types.** `TypeKey::RawPtr { mutable, target }` is new (`runtime/shape.rs`, `ShapeCategory::Pointer`, always `Copy`). A fn pointer uses the already declared but unused `TypeKey::Function { params, result }`.
- **Values.** Both are `ValueKind::Reference` values (kind 9) over a `ReferenceRecord`, so every existing path that copies, stores, passes, drops and validates a shared reference keeps working with no new value kind. The record has `access: Shared`, `owner: None` (so the value is `Copy`) and a new `raw: bool` flag. The flag changes exactly two behaviours: a dereference through the record is always writable, and no lease/epoch decision is made about the *pointer value*.
- **Provenance.** `ReferenceLease::Location | Elements | Buffer` are reused unchanged for pointers made from a reference, a slice or a `&str`. New `ReferenceLease::Detached(u64)` is an address with no provenance (null, `usize as *const T`, one-past-the-end, the result of arithmetic). Using a detached pointer re-derives a lease from the address table at the moment of use; a failure is a dangling-pointer fault. This is looser than rustc, which calls it undefined behaviour. The record's `target` stays the type of the cell actually designated; the pointer *value's* static type (`TypeKey::RawPtr.target`) may differ, which is what pointer-to-pointer casts (`*const T as *const ()`, `*mut c_void as *mut T`) change.
- **Places.** A raw pointer dereference is `Place::deref(record)`, the same root a reference uses. `GuestStore::dereference_place` accepts `TypeKey::RawPtr` next to `TypeKey::Ref`; `resolve_place_windowed` treats a `raw` record as writable and resolves a `Detached` one through the table. Reads and writes then run the ordinary place operations.
- **Addresses.** `p as usize` is a stable synthetic address from a deterministic table in the `GuestStore` (`runtime/cell_pointers.rs`, `PointerTable`), never a host pointer: a cell receives the next aligned address on first request (a root cell a fresh range; a struct/tuple field the parent's address plus the C-layout offset of the live sibling cells; an array element the array's address plus `index * stride`; a `Vec` element its heap buffer's range, one per vector object). The reverse map answers `usize as *const T`, selecting by address and pointee type. Round-trips are exact; addresses never depend on the host. Null is address 0. A function item has one code address per callee identity, so fn pointers compare, hash and cast like data pointers. The size model is a best-effort `size_of` (scalars exact, arrays `n * element`, structs the sum rounded to maximum alignment); it feeds only pointer strides and `p as usize` differences.
- **Arithmetic.** `p.add(n)`, `offset`, `sub`, `offset_from` are address arithmetic scaled by the pointee stride, then re-resolved lazily (detached result). `a.as_ptr()` and `as_mut_ptr()` on arrays, slices and `Vec` are pointers to element 0 (a `Location` lease of the first element cell, or a detached end-of-buffer address for an empty sequence).

## Source types and the written-type kernel

- `TyTerm` gains no variant. A raw pointer is `TyTerm::Nominal(RAW_PTR_CONST | RAW_PTR_MUT identity, [Type(pointee)])` (`traits/pointer_terms.rs`), a reserved-identity nominal like the callable identity already used by `descriptor_source_term`; substitution, unification, impl matching and open type arguments therefore work through the existing `Nominal` arms. `fn(A) -> R`, `unsafe fn`, `extern "C" fn` are `TyTerm::Function`, already produced by `symbolic_headers::function_type`; the ABI and `unsafe` qualifiers are not part of the runtime type (looser than rustc), so they no longer refuse.
- Every walker over `ast::Type` that already handles `RefType`/`SliceType` handles `PtrType`/`FnPtrType` next to them: `syntax/let_annotations.rs` (`AnnotationShape::Ptr`, `::FnPtr`), `db/let_annotation_thunk.rs` (`WrittenType::Ptr`, `::FnPtr`), `ir/written_type.rs`, `frontend/source_types.rs` (`resolve_written_type`), `syntax/signatures.rs` (`lower_type`), `syntax/symbolic_headers.rs`. A written pointer is *not* `exact()`: like a slice or trait-object pointee it is reached through a coercion, so a typed `let` and a call argument go through the coercion sites below.

## Casts and coercions: extending the existing routes

- **Coercion sites** (typed `let`, call argument, `ResultTransfer`, declared result) already ask `GuestStore::unsizing_coercion(value, expected)` and apply `coerce_unsized_value`. These two get the pointer coercions as additional arms (`&T -> *const T`, `&mut T -> *mut T | *const T`, `*mut T -> *const T`, fn item or non-capturing closure -> fn pointer). `Op::BindLocal` consults one more admission (`written_pointer_coercion`) next to `written_unsizing`. No separate pointer-only coercion walker exists.
- **Explicit casts.** `entered_type_thunk::thunk` already routes a cast whose target is not a plain primitive leaf (trait object, unsizing target) to a cast-coercion recipe built by `initial_scalar_thunk`. A pointer or fn-pointer target takes the same route; the recipe emits the new `Op::PointerCast { source, target: Arc<WrittenType>, destination }` after the operand's ordinary evaluation. The runtime operation is `GuestStore::pointer_cast(value, target)`: reference or pointer to pointer (retype, array decay `*const [T; N] as *const T`), integer to pointer (sign extended, `0` is null), fn item or fn pointer to fn pointer or pointer, pointer to pointer of an unsized pointee (`as *const [T]`, `as *const dyn Trait`: the lease is kept; a trait object keeps its value's concrete type, as for references). `*const _` takes its pointee from the operand. Pointer to integer is the existing `Op::PrimitiveCast`; its operand read (`enum_cast_operand`) returns the address of a pointer value.
- Macro-emitted, `println!`/`assert_eq!`-nested and hand-written casts all reach `entered_type_thunk` through the same indexed `CastExpr` node, so no macro-specific code exists.

## Calls through a fn pointer

A fn pointer value holds the callee's code address. `RunMachine::select_value_call` already inspects the callee place's type and extracts a `Callable` identity (looking through references); it gains one arm, `TypeKey::Function`, that reads the pointer value, maps the code address back to the function identity and continues exactly as for a function item value (`CallResolver::select_member_function`, `prepare_selected_argument_call`, the closure path for a closure identity). A function item path used as a value already evaluates to a fieldless `Callable` aggregate (`ItemValue::Function`); coercing it to a fn pointer only replaces that aggregate by the code-address value. Generic function items instantiate at the call from the argument types, as ordinary generic calls do.

## Facade

`crates/lrr/facade/core/ptr.rs` becomes ordinary Rust: `impl<T: ?Sized> *const T { is_null, add, offset, sub, offset_from, read, cast, as_ref ... }` (and `*mut T`), `ptr::null`, `null_mut`, `eq`, `read`, `write`, `addr_of!`, comparison and `Debug`/`Pointer` impls, over `core::intrinsics::lrr_ptr_*` intrinsics selected like `lrr_ref_eq` (`facade/functions.rs`, `engine/run_facade.rs`, executed by `GuestStore` operations in `runtime/cell_pointers.rs`). Anything expressible in Rust over `usize` addresses stays Rust. `&raw const x`/`&raw mut x` and `addr_of!` lower to the borrow of the place followed by the same `PointerCast`.

## Eight failure modes (AGENTS.md)

1. No assertion/macro compiler: casts and coercions enter through the ordinary `CastExpr` and coercion sites. 2. No literal-only generated-expression route: nothing keys on macro output. 3. No context-specific method selection: pointer methods are inherent impls on `*const T` selected by the shared member index. 4. Generated source is not refused: the shape check is on the indexed `ast::Type`. 5. No pattern machinery involved. 6. Lowering prepares the `WrittenType` once per cast node (retained in the recipe); execution looks up the descriptor, never source. 7. No namespace scan: identities are the reserved digests. 8. No body copies: recipes hold `Arc<WrittenType>`.

## Gaps by design (recorded, not hidden)

Provenance is not tracked: arithmetic past an allocation, use after free and type-punned reads through a mismatched pointee are not diagnosed (undefined behaviour in rustc). `repr(C)` field offsets and enum layouts in `p as usize` differences are approximate. `size_of`/`align_of` are not provided by this work. Pointers into `static mut`/`const` promoted storage use the same cell leases as references.

## Implementation notes (October 17, 2026)

What was built, and where the design above changed while building it.

- **Pointers are always addresses.** Every thin raw pointer and fn pointer is `ReferenceLease::Detached(address)` on a `raw` record; `Location` leases are never used for them (a lease would go stale when the pointee is assigned, which defined Rust allows). A dereference re-derives its location from the address at the moment of use (`resolve_place_windowed`, `GuestStore::cell_at`: type-directed, because a struct and its first field share an address). Only `*const [T]` made from a slice keeps the `Elements` lease. `p as usize` is `GuestStore::enum_cast_operand`'s new first case.
- **Descriptors.** `TypeKey::RawPtr` is interned eagerly beside every `Ref` (as arrays intern their slice views), so call contracts can name `*const T` without a mutable store. Fn pointers use `TypeKey::Function`; a function item's value creation also interns `TypeKey::erased_function_pointer()`, the descriptor a fn-pointer parameter or location names when its own signature descriptors are not at hand. All raw pointers are interchangeable at storage contracts and returns (`GuestStore::contract_admits`, `TyTerm` unification of `*const`/`*mut` identities, `same_pointer_family`); the descriptor an intrinsic returns may have an erased pointee (`null()` is `*const ()`) and is retyped at the call return (`restore_caller`) and at every coercion site.
- **One coercion route.** `GuestStore::unsizing_coercion`/`coerce_unsized_value` gained a `pointer` arm (`&T`/`&mut T`/raw pointer to a raw pointer type, a fieldless callable to a fn pointer). Because `WrittenType::materialize` interns a written pointer (although `exact()` stays false), the slot an annotation or parameter hints carries a strict pointer descriptor and `Frame::write_unsizing` converts whatever producer writes there: borrows, locals, calls, item values (`ItemValue::Function`), statics. No pointer-only walker exists. Call arguments reach it through new arms in `prepare` (`pointer_coercion_view`, the `TyTerm::Function` arm).
- **Explicit casts.** `Op::PointerCast` (tag 67) after the operand's ordinary evaluation; `GuestStore::pointer_cast` is the single conversion. `x as &T` and `x as A` (a named non-primitive target) take the existing cast-coercion recipe (`entered_type_thunk::coercion_cast`).
- **Intrinsics.** `core::intrinsics::lrr_ptr_{null,null_mut,offset,offset_from,read,write,retype,as_const,as_mut}` and `lrr_slice_as_{ptr,mut_ptr}` (`facade/functions.rs`, `engine/run_facade.rs`, `runtime/cell_pointers.rs`); everything else (`is_null`, `addr`, `add`, `sub`, `PartialEq`, `Clone`, `ptr::eq`) is Rust in `facade/core/ptr.rs`. Impls on `*const T`/`*mut T`/`fn()` register under the reserved identities of `traits/pointer_terms.rs` (`member_index`), and receivers select them in `run_methods`/`reached_self_type`. One `impl PartialEq for fn()` serves every fn-pointer signature.
- **Numeric constraint service** (arms only, files owned by the numeric work): `TypeShape::RawPointer`, `written_term`, and `*p` of a pointer term in the prefix rule and in the two projection helpers. These let `assert_eq!(*p, 41)` and `let p: *const i32 = &x` with an untyped `let x = 5` infer.

### Known gaps (minimal witnesses)

- `&raw const x`, `&raw mut x` and `ptr::addr_of!`: `raw pointer borrow is outside the live profile` (`syntax/thunks.rs`, `REF_EXPR`); needs a second value slot to hold the borrow before `Op::PointerCast`.
- A call whose callee path names a `static`/`const` holding a fn pointer (`static F: fn() = foo; F()`): `callee classification requires later call context integration` (`select_named_callee`); the callee should be a value call.
- `type F = fn(i32) -> i32;` used as a cast target or `let` annotation: `entered Type alias needs contextual normalization` (`entered_type_goals.rs` only normalizes primitive aliases).
- `assert_eq!(g(1), 2)` with `g: fn(i32) -> i32` and an untyped literal: the numeric relation for a call result is only built for source callees and closures (`Callee` in `binding_constraints.rs`).
- A non-capturing closure coerced to a fn pointer and then called: `select_closure_call` expects the closure value's place.
- `Box::into_raw`/`from_raw`, `Rc::into_raw` (the alloc facade); `mem::transmute` (`nullable-pointer-ffi-compat.rs`), `size_of`/`align_of`; `*const dyn Trait` method calls; pointers to unsized values beyond `*const [T]` made from a slice.
- Provenance and layout caveats are as in the design section above.
