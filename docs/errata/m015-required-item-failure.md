# E-M015-006: malformed owned item output retains its primary discovery failure

The minimal pure LRR supplement expands an actual declarative rule whose output
is lexically valid tokens but invalid item syntax: `struct A { inner }`. The
immutable exact-key record is rejected with `LRR-E-MACRO-OUTPUT`, beginning
`invalid Items expansion:`. A subsequent poll returns successful pending work
instead of retaining that primary diagnostic. The fixed-source witness contains
one strict failing test and a passing independent foreign-reply control. This
witness does not establish a successful catalog or a second native callback.

Revision 4 sections 50.6, 51.3 and M015 distinguish expansion failure from absence
and pending input. Within the current request, failure retention prevents a caller
from interpreting the same immutable rejected output as fresh expansion work.
The selected repair records the item-admission diagnostic only after exact pending
source identity and explicit compiler/procedural authority checks. A reply from
another request is refused without poisoning the owned pending work. No query
provider executes macros, and no budget charge or seal is committed on rejection.
The supplement requires repeat poll/admission, seal/publication/catalog refusal
and unchanged database revision to preserve the same primary failure, with no
signature/body/thunk query. A valid owned reply following a foreign rejection
must still publish its real one-test catalog.

A second strict witness reproduces the same retry hole through a real nested
generated item invocation, retaining its exact demanded key. Its repair preserves
ordinary and generated foreign-reply refusal and prior accepted-output accounting.
This bounded ordinary/generated-source correction does not cover every generated
module, derive or argument path. The independent official derive-bad MacroRun attempt reaches adapter procedural grammar validation
and rejects invalid Items before schema construction and database adoption. The initial harness assumed
a successful validated output reaching append, so it fails that prerequisite.
Its corrected real-boundary control and callback counters remain under validation;
no production derive-append defect is established by that failed harness.
No full stock fixture, selected guest body or Linux acceptance is claimed.
