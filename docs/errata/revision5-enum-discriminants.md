# E-R5-013 — Enum discriminant expressions are anonymous constants run by the ordinary interpreter

October 17, 2026. Implementation record (not a spec contradiction). Extends E-R5-007 (const/static initializers run through the VM) to the one remaining preparation-time constant the pure evaluator was said to own: an explicit enum discriminant that is not a plain integer literal. E-R5-006 applies (looser than rustc, no resource accounting); E-R5-005 applies (one pipeline).

## Invariant

A discriminant expression `V = expr` is an anonymous constant of the enum's representation type (`isize`, or the `#[repr(<int>)]` integer) whose scope is the enum's scope. It is evaluated by the same machinery as every other reached constant: the ordinary body index, name resolution, source constraints, lowering, VM and drop glue, as an initializer frame entered through `RunMachine::demand_initializer` / `enter_initializer`. There is no discriminant evaluator, no expression-shape whitelist and no second table of values. An implicit successor is the previous variant's discriminant plus one (the existing table rule applied to an evaluated predecessor). The plain integer literal (optionally negated) stays on its existing fast path (`NominalSchema::literal_discriminants`); it enters no frame.

## Minimal witnesses (unchanged upstream, `fixtures/upstream/rustc-checkout/tests/ui`)

`enum E { A = 1 << 3, B = BASE + 2, C, D = (3 * 5) as isize, F = -1 }` then `E::A as i32` stopped with `LRR-E-UNSUPPORTED: enum discriminant expression requires constant evaluation`, as did eleven upstream fixtures: `consts/const-eval/enum_discr.rs` (`Y = Foo::X as isize - 3`), `consts/const-block-non-item-statement-rpass.rs` (`Bar = { let x = 1; 3 }`), `consts/const-repeated-values.rs` (`*[&FOO; 4][3]`), `enum-discriminant/issue-50689.rs` (`(|x: i32| { }, 42).1`), `enum/issue-23304-1.rs` (`0x1FFF0u32 | (ValueType::INT32 as u32)` under `#[repr(u32)]`), `enum/issue-23304-2.rs`, `numbers-arithmetic/signed-shift-const-eval.rs`, `resolve/resolve-issue-2428.rs`, `enum-discriminant/enum-discriminant-const-eval-truncation-9837.rs`, `structs-enums/tag-variant-disr-val.rs`, and `cast/cast-enum-const.rs` (a block-local enum naming a block-local `const`). All eleven now complete (edition 2021 run, hand-back report lists the commands).

## Shared entry points extended

- **Declaration rows.** A cfg-enabled variant whose `= expr` is not a plain integer literal gets one ordinary initializer declaration row (`ItemKind::Constant`, `ItemOutline` with a `BodyHandle` over the expression and `declaration_span` over the variant). Its identity is `discriminant_def_key(enum, variant).fingerprint()` (`syntax/outline.rs`), a pure function of the enum's `DefKey` and the variant name (the name `Enum::Variant` is unspellable, so no namespace candidate and no collision), which lets the runtime derive it from a type descriptor with no table. Module enums carry the rows in `ItemOutline::discriminants` (`ParsedFile::discriminant_rows`); source preparation publishes their header/source/context/body inputs exactly like every outline item (`Outline::declaration_rows`, both loops in `source/changes.rs`), and `PreparedSourceView::outline_item` finds them. Block-local enums carry the same rows as declarations owned by the enum, in `EnteredMacroFacts::members` next to the associated items of block-level impls (`BodyItemBudget::collect_discriminants`, called from `entered_macro_facts`); publication, signing and admission are then the existing local-member route (`publish_local_declaration`, `ordinary_local::admit_container_member`, `prepare_reached_local_source` member mode).
- **Signature and body.** `ParsedFile::initializer_signature` (`syntax/signatures.rs`) returns the zero-parameter signature of a `Variant` row with the enum's `#[repr(<integer>)]` (else `isize`) as the declared result; `body_index::is_initializer_owner` makes the `ConstArg` of a `Variant` an initializer owner for `entered_body_root` and `thunks::initializer_result`, exactly like `Const`/`Static`. The body is the existing non-block initializer root (`ScopeKind::Initializer`), so numeric literals take their type from the declared result through the ordinary source-constraint service (witness: `#[repr(u64)] enum Huge { A = 1 << 40 }`).
- **Lookups.** Every site that finds a declaration or its owning source by definition identity or body key now also consults the rows: `declaration_rows()` replaces `items` in the body-context owner lookup (`source_body_context.rs`), the lexical-outline join (`local_type_modules.rs`), the macro boundary (`source_macros.rs::enter_prepared_body`), constructor/owner lookups (`run_constructors.rs`, `changes.rs`) and local publication/return-type preparation (`local_declaration_inputs.rs`, `declaration_return_types.rs`, `local_type_names.rs`). Name-table builders, member indexes and the other iterations over `outline.items` deliberately do not see the rows.
- **Demand.** `CallResolver::initializer` resolves the row like any const (module rows by outline, local rows by `admit_container_member`); `RunMachine::demand_initializer` / `enter_initializer` / `resume_initializer` (`engine/run_initializers.rs`) run it once and cache the scalar in the run-long `const_cells`, keyed by the row identity. The dispatcher's pre-step (`engine/run_enum_discriminants.rs`, called before the initializer-demand check in `engine/run.rs`) probes each `Op::PrimitiveCast` operand with `GuestStore::pending_enum_discriminant`; a pending variant demands the nearest preceding explicit row (`NominalSchema::expression_anchor`), and the evaluated value merges into the descriptor's table through `attach_discriminants` (now an agreement-checked refinement) with its implicit successors (`NominalSchema::anchored_discriminants`). The cast itself (`GuestStore::enum_cast_operand`) is unchanged: it only reads the table, and values above `i64::MAX` in a `u64` repr cast as `u64`.

## Alternate routes removed or not added

No pure-evaluator route for discriminants (`literal_discriminants` is only the literal fast path); no VM entry for literals; no recognizer for `1 << 3`, `X as isize`, blocks, closures or array indexing (all go through the same body); no per-macro, per-assertion or per-cast-context handling (the cast operation is the same `PrimitiveCast` handwritten, in a user macro, through a wrapper macro and inside `assert_eq!`/`assert_ne!`/`format!`); no synthetic function wrapper around the expression; no second table of values.

## Costs

Cold: one outline row per non-literal explicit discriminant at source preparation (no parse beyond the existing outline walk; a file without such discriminants builds and encodes exactly as before), and one initializer-frame entry per evaluated explicit variant per run, on the first `as` cast that needs it. Hot: a cast of a value whose table entry is known costs one store probe in the dispatcher's pre-step and the existing table lookup; a cast of a scalar returns from the probe at the first value-kind check. After the table is complete no source or database work happens.

## Evidence

`cli/enum_discriminant_tests.rs` (six programs, each in editions 2015/2018/2021/2024, expected output is real `rustc +1.99.0` output, all four editions agree): every written form; repr widths with negative, truncating and above-`i64::MAX` values; discriminants naming other discriminants (earlier, later, chains), `const fn` calls and control flow; discriminants flowing into consts, statics, derives, modules and collections; casts nested in user macros, a wrapper macro, `assert_eq!`/`assert_ne!` and `format!`; block-local enums (function, nested block, closure, and a statement macro whose `expr` fragment is the discriminant). Unit tests: `syntax::outline` (rows are unpublished anonymous constants), `frontend::nominal_constructor_tests` (anchors and anchored tables).

## Known gaps (recorded, not hidden)

October20 source checkpoint update: source-selected `discriminant_value` now
shares the cast initializer coordinator before its arguments seal; it no longer
substitutes an ordinal for a pending expression. Ordinary VM initialization,
run-long constant storage and table refinement remain the same mechanism.
Installed recipes retain the cast operand index instead of rebuilding it per
preparation visit. [V485–V486 evidence](../../worktracks/evidence/2026-10-20-v485-v486-discriminant-initializers.json)
records32LRR adaptation runs/16repeat pairs across all editions and origins;
these do not pass the unchanged generic `repr128.rs` main. The projected field
type in the `mem::Discriminant` facade, nonliteral layout demand and the other
unexecuted/source-publication matrices remain incomplete.

- **Layout.** `size_of::<E>()`, `align_of::<E>()` and the layout of types containing `E` still refuse an enum whose discriminants include an unevaluated expression (`engine/run_layout.rs`, E-R5-012). The layout demand still needs ordinary VM initializer preparation; the discriminant-value call path is now joined as recorded above. The `mem::Discriminant` facade's fixed-isize field still needs the common associated-type/field integration.
- **Module-level macro-emitted enums.** `make_enum!(E)` at module level, with literal or expression discriminants alike, fails at `E::A` with `LRR-E-NAME-MISSING` because generated enum variants are not admitted into the name graph (`NameNamespaces::admit_enum_variants` runs for original outlines only). Unrelated to discriminants; the rows of generated units are computed with the unit's outline but not published (`generated_syntax.rs`), and `prepare_enum_discriminants` reports that explicitly.
- **Macros inside a discriminant expression** (`Q = twice!(4)`) hit the general generated-expression lowering gap (`const X: i32 = twice!(4)` fails the same way).
- **Local enums with `#[derive(..)]`** (baseline gap: the derive producer on a block-local enum leaves the body's macros unresolved) and a body that mixes a macro expansion with a local `const` (baseline: the pure evaluator no longer reaches the local `const`).
- **`#[cfg_attr(.., repr(u8))]`** is not consulted for the discriminant type; a plain `#[repr(..)]` is. Overflow of the repr type and duplicate discriminants are compile errors in rustc and are not diagnosed (E-R5-006).
