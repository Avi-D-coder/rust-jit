# E-M009-002: explicit matched protocol selection

The pinned proc-macro client chooses its bidirectional span-callback codec through RUST_ANALYZER_USE_POSTCARD and a compiler-version argument. M009 must use an explicit immutable session configuration without mutating global environment or restarting a possible macro invocation. Legacy JSON does not carry the source-text/file/line/byte-range subrequests implemented by the pinned bidirectional codec.

The narrow additive API with_io_channels_protocol selects exactly one existing ProtocolFormat, bypassing ambient format selection. It reuses the original process initialization, version check, span configuration, message codecs and pool. It requires current API6 plus rust-analyzer spans before loading any macro library. Default public methods retain their original behavior. There is no inference/HIR/native backend or source-pin substitution.

Two patches against the original archive expose the selector and pass the explicit format into the original run loop. The original archive and file inventory are retained; UPSTREAM.toml has patch/preimage/postimage hashes. Bootstrap and patch-proof tests must reconstruct each exact changed image and reject tampering. Actual macOS Rust1.99 external sessions now exercise the selected codec. A native compiler oracle matches captured Unicode source_text, file/local_file, line/column and start/end positions. The client rejects malformed or unknown private anchor encodings before conversion; plain file queries and editioned anchored queries use their distinct pinned encodings. Captured bytes are content-checked and local-file capability changes invalidate demand/session identity. Source ancestry and cross-anchor join acceptance remain pending. Rust1.99 rejects stable byte_range use (E0658); no native byte-range acceptance is claimed.
