# M013 discovery macro routes

Original item invocation demands now use SourceMacroIndex's existing invocation
resolver. Textual precedence remains first; imported and qualified candidates use
the existing SourceMacroRoutes and MacroNamespaces engines. Routes read the actual
completed textual index after earlier expansion publication. Partial discovery
graphs retain exact textual producer demands as pending buckets; the strict
candidate-graph API continues to reject unresolved textual imports.

Requests bind the selected canonical macro definition to its captured owner.
Definition bodies and consumer arguments retain their separate captured source
identities, editions and hygiene contexts. Expansion remains an explicit request
action. No query provider executes macros or build tools.

The ordinary import worklist accepts an exact resolved macro facet while continuing
to resolve value and type facets. Qualified import proof requires both its target
and destination to resolve to the same definition. Textual import proof comes from
the completed index at that import's source position. An unrelated export with the
same alias cannot satisfy an unresolved target. Facets are bounded, immutable within
one discovery and included in the import convergence fingerprint. Route catalogues
have checked aggregate metadata accounting.

Eight controls execute qualified exports, imported aliases, cyclic reexports with
an originating macro, later imports of a generated textual macro and an export owned
by an inline module. Unresolved macro/import cycles cannot publish a partial seal;
a same-named export cannot satisfy a missing import target. A reproduced ambiguity
regression requires textual import destinations to select the same unique definition. Initial failures and
diagnostic inspection logs are retained. The cycles exposed that the ordinary
worklist needed the resolved macro facet even after macro selection succeeded.
