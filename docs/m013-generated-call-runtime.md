# M013 generated function call runtime

Completed source discovery can now install its immutable original source catalogue
and actual closed name graph into RunMachine. Publication and the matching
discovery-certificate query must succeed before entry. Generated callable selection
preserves the canonical GeneratedItemKey identity separately from replayed DefKey
metadata. Generated callers validate their owned syntax through ParseFile and use
the captured declaration scope for ordinary value lookup.

Signature-name resolution now accepts immutable database declaration inputs.
Existing argument contracts, explicit generic arguments and return descriptor
checks use that path for both original and generated declarations. The existing
VM and source-call dispatcher execute the bodies; query providers do not expand
macros or run tools. Generated declaration metadata has checked retained-size
accounting.

Six runtime controls exercise original calls through generated import aliases,
generated-to-generated calls, generated-to-original calls, explicit generic
arguments from a generated caller, rejection of a wrong generated return type,
and certified missing-name rejection before argument-body preparation. The first
runtime attempt exposed an original-only return-definition lookup. That lookup
was repaired through the same database signature-name path; the failed log is
preserved as ordinary implementation evidence.

M013 remains in progress. Generated-body macro contexts, macro namespace
import/export and qualified/contextual/definition-unit routing, generated aliases
and other symbolic type paths, external-module chains, overlapping origin cases,
remaining quota/failure boundaries and full MX027/MX028 acceptance remain pending.
M014–M016 follow in fixed order. No full fixture, release or Linux acceptance is
claimed. Validation targets macOS ARM64 with Rust 1.99.0.
