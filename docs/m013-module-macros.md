# M013 generated module item-macro scopes

M013 remains in progress. Generated macro catalogues retain a bounded ordered
source-module-to-lexical-scope index and an exact invocation-to-source-scope index.
Inline module scopes freeze their parent visibility at the actual opening position.
Definitions and invocations use their module scope in the existing hygienic
textual resolver and path namespace. Captured original scopes enter outside the
oldest generated ancestor rather than pretending a generated module was an
original captured module.

Child admission validates the exact pending request and its actual source scope.
Recursive outputs retain that owner in header/query publication, route snapshots,
frontier retirement and strict selection revalidation. Outward definitions carry
explicit source scope: only definitions belonging to the consuming lexical scope
become its textual bindings. Nested definitions remain available by canonical
identity for qualified routes/reexports without leaking into the original parent.
Scope/path and copied child-binding metadata is checked before growth/admission.

Named imports and qualified reexports are resolved through the ordinary macro
namespace. A generated module may not exist during initial graph construction;
discovery now retains a typed module-membership demand with explicit stable path
encoding, then revisits it after producer integration. Strict candidate graphs
continue to reject unresolved membership. Unknown producers remain incomplete;
no negative result or permission to execute a helper is inferred from a wait.

Nine controls cover local/inherited definitions, sibling isolation, recursive
outputs, macro imports, parent non-leakage, lexical shadowing, qualified reexports
and the actual native parent-scope rejection. The VM executes seven new successful
examples. The native matrix now compares twenty-four successful VM/native cases,
seven earlier E0659 cases and one missing parent-scope macro rejection. All native
copies are isolated explicit oracle preparation, never selected live compilation.

The original failures, intermediate wrong access/frontier scope failures and early
unresolved-membership failure are retained. These are implementation repairs,
not pinned-backend contradictions. No query side effects or macro/native authority
changes are introduced.

Macro-use inheritance and complete cross-fragment module linking, Cargo/world/
definition-unit facets, origin invalidation, generated-body runtime macros,
return/generic aliases, full quota/failure boundaries, complete MX027/MX028
fixture/JIT acceptance and release remain mandatory. M014–M016 follow the fixed
Section 57 order. Evidence is macOS ARM64 Rust 1.99.0; Linux remains a later port.
