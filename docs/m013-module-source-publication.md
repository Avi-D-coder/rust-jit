# M013 atomic child source publication and guest execution

M013 remains in progress. Discovery publication now supplies its actual completed
ModuleSyntaxInput projections to the existing private database publisher. Each
projection must match an adopted ModuleRecord identity and observed input stamp,
be included in the published source set, and have its actual parent expansion
descriptor in the seal. Every expected source row must be present with the exact
fingerprint. Conflicting module row identities and substituted/incomplete projection
rows refuse before mutation. Only keys from those validated projections receive
the additional source-row permission; other unexpected derived input kinds refuse.

The original and physical child captured source, blob and cfg rows participate in
source validation and scanned-outline dependency checks. Existing compiler stamps,
record descriptors, immutable row conflicts, counts and metadata/source budgets
remain checked. Source rows, generated rows, records and seal commit in one derived
revision. Replay is idempotent. This does not replace the base source revision.
Adopted module captures already account for the shared source blob storage.

Runtime and callable source catalogues now retain the completed physical child
PreparedSourceViews as well as original views. The guest can therefore resolve and
enter a real child function against the published source/declaration/body facts.
No selected live unit is compiled; the native comparison compiles a separate oracle
copy. Existing cold declaration/body handling remains lazy.

The updated namespace publication control verifies every actual child projection
row and idempotent replay. A new stale-input control verifies no partial child rows
or discovery seal enter a changed database. A new macOS Rust 1.99.0 oracle executes
an actual macro-emitted external module, calls child::made() in the guest and native
copy, and compares observed results. Both produce 1583 from the real function body.
This is explicit coordinator API acceptance for the simple external module case.

The historical CLI/native module witness remains unchanged and pending. CLI/service
capture/adoption driver integration is not proved by API execution. Complete
namespace facets, nested physical module layout/context, child compiler/body macro
routing, macro-export/cache invalidation, quota boundaries and broader generated
source/runtime/type interactions remain required. Full MX027/MX028, JIT, release
and Linux acceptance are unfulfilled. macOS ARM64 Rust 1.99.0 remains primary.
