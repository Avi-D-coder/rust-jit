# M013 explicit original-source derive execution

Original-source discovery now resolves the first nonempty derive group into
exact helper declarations followed by an immutable execution selection. Enabled
member annotations must be known inert attributes or bare helpers introduced by
that group's exact receipts with the same original source context. Unknown and
qualified member annotations retain the incomplete producer. Later outer groups
and replacing/helper attributes remain in the occurrence input; their subsequent
processing is not certified by this selection.

The selection binds captured-source/item/producer origin, scope, input occurrence,
catalog, definition and receipt fingerprints. The request carries a private
selection proof. An attribute request cannot substitute for it, duplicate binding
is refused, and only the exact pending request may execute. MacroRun requires
separate authority, current database/source epoch, the owning shared budget and
matched prepared session. Execution remains outside pure query providers and
does not run build tools or compile the selected live unit.

The authorized run executes once, adopts the real output and retains its exact
descriptor. Discovery then returns an explicit source-derive append demand.
Repeated polling retains that demand without executing again. The original
producer's ticket remains active, no original declaration is prematurely restored
and publication is refused until output integration completes. The output is a
real macro record; no synthetic parent record represents the original source.

The controlled positive uses the unchanged imported `derive-helper-configured.rs`
as its source shape. Adaptations outside the licensed directory alias the fixture
CheckDeriveInput export as Empty, use cfg(all()), use its declared helper name and
add repr(C) for that macro's input assertions. The actual output declares
DERIVE_INPUT_ATTRIBUTES with literal 2_usize. Its observed native invocation and
accounted expansion counts are both one. Permission denial and foreign-run
execution remain at zero. This is execution of the controlled prepared export,
not execution of the original rustc auxiliary or a full language-fixture pass.

Existing metadata and repeated-occurrence controls now stop at a bound execution
demand with zero invocations. New unknown/qualified member controls stop earlier;
a captured-source revision change refuses dispatch with LRR-E-QUERY-REQUEST and
zero invocations. The initial positive regression failed because no original
execution demand existed. Harness compiler/API and stale-diagnostic expectation
corrections are retained without changing production refusal semantics.
