# M013 generated item input admission

GeneratedItems admits only the exact demanded Items ExpansionKey and a nonzero
current discovery epoch. A procedural record must carry that same epoch. This is
transport/syntax admission, not permission to run a procedural macro. Macro
execution remains with the separately authorized matched-server service.

The pinned adapter imports schema2 token trees and calls its existing token-tree
to-syntax bridge with MacroItems grammar and each token context's edition. Grammar
errors refuse the input. The syntax text and every ordered origin range retain
owned span keys; names carry their exact origin keys. The original token forest
and expansion record remain immutable alongside the syntax view. No plain-text
macro expansion or alternate parser/transcriber is used.

Top-level generated headers receive GeneratedItemKey(expansion, structural path,
header digest). The header digest uses explicit kind tags, header text and bounded
relative origin records. Function/module/trait/impl body syntax remains outside its
header range; the full output and origins retain it for ordered later consumers.
Origin ranges are found by binary search rather than scanning every token for each
header. Root ordinals preserve item order. Associated/nested declaration traversal
and declaration cfg/transforms require the later integration/scanner work.

The actual pinned hygienic macro control emits an import, another macro_rules
header and an ordinary function containing a cold invalid type/call. Its item syntax
and origins are admitted without executable preparation or type inference. Other
controls reject mismatched keys, zero/stale epochs and invalid item grammar, and
check that function header ranges exclude body text. The procedural-key stale-epoch
control is a negative transport test; no procedural helper executes.

Wire, input metadata, text, origin-count and header-count allowances are checked;
owned vectors reserve fallibly. Host/runtime and adapter token models cross their
existing explicit schema2 wire boundary. These controls do not prove MX027/MX028:
SourceDiscovery must still integrate the generated headers/imports/macros with
scope/hygiene facts, revisit blocked work and publish query seal dependencies.
Full generated attribute/derive/cfg/module and nested scopes, producer quotas and
final fixture observations remain required. M013 and the project stay in progress.
