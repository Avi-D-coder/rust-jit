# M013 source expansion admission and discovery retries

SourceDiscovery can freeze pure declarative preparation before polling begins.
A ready original item macro produces NeedExpansion with an immutable request.
Repeated polling returns that same pending request; discovery itself executes no
matcher, procedural macro, build tool or guest operation. Explicit caller expansion
returns a record, and admission requires the exact frozen request key and epoch.

Enabled original invocations now retain their ordinary namespace frontier identity.
A deterministic index records every producer sharing that frontier. Completing one
of several identical invocations cannot clear the shared frontier early. Parse and
attribute frontiers without a completed producer remain unresolved.

Admission validates generated item grammar, caller scope/context and captured cfg,
and prepares ordinary generated headers and imports through GeneratedHeaderPlan.
The cumulative wire/header budgets, generated job count and scheduler update are
preflighted before namespace publication. Namespace registration retains its guard
until completion. A publication failure poisons discovery and cannot produce a seal;
complete publication-failure injection acceptance remains pending.

After successful publication, completed original frontiers are released, the existing
named/glob import fixed point runs again, and actual generated import jobs are queued.
The discovery update contains canonical generated header identities and exact record
dependencies. Changed membership wakes blocked work. Empty expansions still contribute
their completed invocation/record identity, so they can unblock later demands. The
original textual producer is discharged with the existing TextualScopes publication
operation only when no unresolved generated producer or macro binding remains.

Generated macros, modules, impls, transformations and contextual imports that still
need integration retain explicit jobs/frontiers; they do not become empty source.
Lookup remains unavailable until all queued work completes. A published seal forbids
later expansion admission. This is source/header/import integration, not complete
MX027/MX028 acceptance or query-database seal publication.

Five controls use actual original-source hygienic expansion: an original import
resolves a generated function with canonical identity; repeated identical empty
invocations complete separately; a generated import alias chain resolves; substituted
records and post-seal admission refuse; and generated unknown producers keep the
catalog incomplete. Existing scheduler controls exercise ticket/dependency/limit
refusal and wakeup behavior. Remaining work includes generated outward macro bindings,
cross-fragment ancestry, generated invocation scheduling, nested/module/attribute
integration, definition-unit imports, full producer quota boundary controls, query
seals and MX027/MX028. M013 stays in progress. Validation is macOS ARM64/Rust 1.99.0;
Linux and release acceptance remain pending.
