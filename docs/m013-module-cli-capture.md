# M013 CLI module capture and adoption

M013 remains in progress. The standalone CLI now drives generated external-module
demands through the existing explicit source capability and expansion coordinator.
It records a phase-bound capture request, starts and accepts that exact reply,
adopts the immutable module record, and stages its physical source projection.
Discovery continues until the actual child producers and requested namespace are
complete. Only then does it publish the child source rows and seal and start the
guest. Unresolved child producers preserve an incomplete outcome.

A deterministic index reconstructs original physical file-module directories from
captured source views and the existing module layout rules. This pass reads the
captured blobs and cfg, with no filesystem access. Count, queue and metadata limits
are checked. Physical caller identity selects its retained directory; the driver
refuses an absent or unsupported inline/generated caller context. It never guesses
a directory from a logical module name. Capture itself is an explicit coordinator
operation using the prepared source authority. Query providers do not read files,
run tools or execute macros.

The existing empty-module regression now requires the actual child function to be
executable while an unrelated erroneous cold body remains unentered. Its previous
expected uncaptured refusal is preserved in the failed gate artifacts.
Eight additional acceptance controls exercise actual CLI execution: the historical simple
macro-generated external module, a macro in an original nonroot file, a physical
path override with a competing root file, missing and ambiguous candidates,
unknown child macros, an actual parent macro invoked in the child, and a cfg-disabled
module. Successful controls inspect the real guest report. Refusals require exit 2,
empty stdout and the specific diagnostic. The historical witness source is compared
with an explicitly compiled isolated Rust 1.99 macOS oracle copy; its native output
is compared to the actual CLI value. The selected live source is never compiled.

The earlier failed witness remains immutable in
`artifacts/macos-first/m013-module-frontier-native-witness.json`. New comparison
artifacts provide fresh evidence that its simple CLI case succeeds; they do not
retroactively change the earlier observation. The complete MX027/MX028 fixture
matrix, service coordination, nested physical/generated and inline module layout,
child compiler/body macro routing, cache invalidation and quota boundaries, broader
runtime/type interactions, JIT and release acceptance remain pending. Linux is a
later port.
