# M017 function-pointer reference elision — isolated component candidate

The invariant is that each omitted or `'_` reference lifetime in a safe Rust function-pointer input receives a fresh region slot in that pointer's binder. Explicit `for` lifetimes retain their existing slots; definition lifetime/type/const parameters remain rigid. An omitted or `'_` output lifetime reuses a region only when exactly one input parameter contains exactly one distinct applicable region. Nested function signatures have independent candidate sets, including when their references name an outer region. Every nested function pointer still contributes a de Bruijn scope, including an empty binder.
