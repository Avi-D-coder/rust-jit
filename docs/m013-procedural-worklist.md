# M013: original procedural producers in source discovery

Revision 4 Sections 50.2/50.5/50.6 and fixed Section 57 milestone C.
macOS ARM64 Rust 1.99.0 first. M013 and release acceptance remain incomplete.

Invariant: an original function-like procedural producer retains its source
frontier until its exact owned request is assembled, executed through the authorized
coordinator, adopted into the database and integrated into the existing worklist.
Resolution, polling, assembly, records and seals grant no native execution authority.

The prepared procedural catalog now carries the Cargo consumer, direct macro
aliases, graph, epoch, compile environment and immutable preparation fingerprint.
Its stable encoding and checked metadata bind these facts to discovery. The existing
macro route/name indexes merge its export facets, preserving canonical identity.
A catalog from another graph/epoch/environment/consumer refuses before work.

Discovery suspends with an owned procedural selection, then binds only the matching
source request. Pure expand refuses native execution. The native record must already
be adopted by the coordinator: a matching key alone cannot admit fabricated output.
The existing shared expansion accounting covers actual source integration. After
integration, generated imports/macros use the same declaration worklist. Before
sealing, original procedural selections are re-resolved against final membership.
Late ambiguity cannot yield a partial certificate or publication.

Sealed discovery retains sorted, bounded prepared catalogs and their fingerprints.
The database checks catalog ownership/order/epoch and complete dependency receipts
before atomic publication. The internal discovery-input stable encoding advances
to its procedural-catalog domain; this is an explicit owned encoding change.
A coordinator epoch transition preserves captured source inputs, increments query
revision, rejects zero/reused/backwards epochs and cannot run during a pure query.
It fixes the observed test setup failure caused by replacing all source inputs with
an epoch-only input publication. The failed attempts remain preserved.

Two actual matched-server controls prepare only the controlled proc tool. One
resolves an import alias, suspends before native work, refuses pure execution and
unadopted/substituted records, executes once, then discovers a generated macro and
import. One generated declarative invocation closes the fixed point; names resolve,
a seal publishes, and a later epoch invalidates the old query while source revision
is preserved. The second emits a conflicting macro import and refuses seal/publication
after one invocation. No native-only comparison replaces this worklist evidence.
