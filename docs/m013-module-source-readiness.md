# M013 physical module source readiness

M013 remains in progress. Source readiness is an explicit prerequisite for eventual
module closure; it is not a namespace seal or permission to release a frontier.
The operation re-observes the adopted source/environment and exact staged
projection, then verifies every retained compiler input stamp against the database.
Input withdrawal and compile-environment changes refuse rather than replaying an
old positive readiness result.

Pending results enumerate real unfinished parse jobs, retained original source
producers, source macro index producers, physical-child generated fragments,
physical invocations without completion, and unfinished imports in the requested
namespace. Pending identities are sorted, unique and bounded. Readiness does not
silently discard unknown producers or treat an admitted unresolved record as a
completed invocation. A known named import can satisfy its actual requested
namespace facet; this does not certify its other facets or the complete module.

A ready result revalidates actual completed generated catalogues using the retained
module parent/ancestor hygiene and source context. It also re-resolves physical
calls and compares their exact expansion keys with admitted records. An indexed
invocation lookup avoids repeated record scans. The result owns an immutable
module syntax lease, completed macro index snapshot, requested namespace and
actual record descriptors. Allocation counts and metadata are checked before the
snapshot is cloned. Its stable identity encodes the discovery context, exact
projection, namespace, observed input stamps, ordered records and imports.

Four controls cover parse-before-readiness, lazy cold bodies, stable replay and
retained source accounting after database input replacement, actual recursive
record/selection revalidation, exact unresolved producer/import identities, known
value-import facets, source withdrawal, and environment changes after positive
readiness. Preparing readiness never publishes database rows, executes a macro,
releases the file-module frontier or permits an incomplete scope seal.

Final module closure must still install child source and macro-export/macro-use
facts, integrate complete namespace facets, register derived source/cache rows,
revalidate final selections and retire only proven frontiers. Nested physical
file-module layout/context, child compiler routing, full invalidation/quota
integration and actual LRR child execution remain required. Full MX027/MX028,
JIT, release and Linux acceptance are unfulfilled. Historical positive module
native/LRR evidence remains pending. macOS ARM64 Rust 1.99.0 remains primary.
