# M013 parked child origin and edit acceptance

M013 remains in progress. These controls validate the existing implementation
against actual Rust 1.99.0 on macOS ARM64; they do not claim a production repair.
A later sibling expansion may provide the exported macro required by an earlier
parked child's import. Its same-named textual macro remains outside the child's
captured lexical source position. Child and grandchild controls execute the
imported function in the VM, and isolated native copies produce the same value.
With the sibling ordered earlier, its unrelated textual origin conflicts with
the generated import: both child depths refuse selection with ambiguity and
prevent seal/record publication. Native Rust rejects both with E0659.

The initial exploratory expectation incorrectly required ambiguity for the later
sibling. Native Rust accepted it, and the live driver continued beyond the guessed
expansion count. The before log is retained as a corrected test assumption,
not a backend contradiction or an implementation failure. The accepted positive
and reverse-order negative controls are based on the actual native evidence.

A fifth control uses one database across successful discovery, a source-order edit,
conflicting discovery and restoration. The edit invalidates the ready seal.
Republishing the captured stale discovery is refused without changing revision;
conflicting discovery publishes no partial records or seal. Restoring the source
rebuilds a complete seal and executes the actual imported function in the VM.
No host tool execution or macro authority is added to a query provider.

The native matrix now has twelve successful VM/native comparisons and seven
actual E0659 rejections. Native copies are explicit isolated oracle preparation,
never compilation/loading of the selected live runtime unit. These are component
controls, not full MX027/MX028 fixture/JIT or release acceptance.

Complete origin overlap/invalidation, Cargo/world/definition-unit facets,
generated-body runtime macro contexts, type/quota/failure boundaries, complete
fixture/JIT acceptance and release remain pending. M014–M016 follow the fixed
Section 57 order. Linux remains a later, separately validated port.
