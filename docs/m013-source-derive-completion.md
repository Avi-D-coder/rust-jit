# M013 original-source derive completion and publication

Original-source discovery can settle an item after every selected derive output
and nested generated fragment completes and the remaining annotations are known
inert attributes or exact bare helpers introduced by current/preceding groups.
The completion proof binds the original outline/path, item header, full cfg/member
preprocessing facts, ordered compiler selections, completed occurrence selections,
helper contexts and receipt fingerprints. It is replayed before the seal escapes.
Unknown and qualified annotations receive no completion grant. Legacy helper
ordering and helpers introduced only by later groups remain separate pending work.

Completion restores the original declaration with its canonical source identity,
retires its textual producer while retaining appended bindings, releases only the
accounted source frontier and refreshes imports. The last step matters: resolving
imports before producer retirement leaves a cached incomplete import even after
the original item settles. The positive regression failed before this refresh;
the blocked-job witness distinguished that import from the derive producer.

The original item uses a source completion proof; no artificial macro record
stands in for it. Actual derive/nested output records and helper declarations
enter the existing exact publication/certificate path. MacroRun still requires
its own native output receipts, current source revision, matched session, separate
macro authority, shared budget and verified captured files. A source edit after
sealing refuses publication. A published original type query becomes ready and
then suspends after its source is edited, rather than reusing the old certificate.

The controls adapt the unchanged copied rustc `derive-helper-configured.rs` outside
the licensed directory. The positive type case preserves the original struct's
canonical identity, seals, publishes, queries the type and verifies invalidation.
The ordered/nested append controls now require successful sealing/publication;
their earlier pending-only acceptance is superseded. A deliberately unknown outer
annotation remains visible in the actual derive input and blocks the original
producer after its real output is integrated. The prepared controlled macro checks
that retained annotation. The stale-publication control executes once, seals and
then rejects publication after a source change without further native invocation.
