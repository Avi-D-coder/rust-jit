# T025 shift count source fallback

Invariant: a shift count has its own source type. Its unconstrained integer variable falls back to i32 independently of the left/result width; written suffixes and existing concrete source widths survive. General future-use inference is still pending.

The integrated component emits i32/f64 fallback only from source-proven closed RHS expressions in ordinary and runtime-macro lowering. A named RHS receives no default from the VM; its existing source width is retained, or it remains explicitly unresolved while general future constraints are pending. It removes the shift-count flag that prevented literal/local-read materialization. Pure admission now checks the selected count width before fuel or numeric execution. It also removes conversion of arbitrary raw counts to u32 in NumericBinary preflight/execution. Concrete negative counts and counts at/above the left width still produce an ordinary InvalidShift guest panic. The existing oversized-literal control now expects a range/invariant fault during materialization; it cannot become an expected-panic pass by evading its source width. Compound shift RHS literals also select i32 independently.
