# M013 certificate-dependent macro namespace membership

M013 remains in progress. Configured declarative discovery now integrates captured
macro/import/export routes before the worklist runs and after each completed
producer, including immediate generated output without nested calls. The final
route integration precedes storing the completed seal. Publication snapshots actual
macro namespace graph outcomes through the existing bounded CertifiedScope builder.
Unconfigured macro discovery continues to suspend instead of certifying absence.

SealedName buckets describe complete module namespace candidate membership. They
have no textual position or hygiene context and do not replace contextual macro
call selection. Duplicate candidate identities remain explicit ambiguity in this
membership query; textual shadowing still uses the existing exact-position resolver.
The certificate binds its actual captured owner edition, scope, namespace and epoch.

The existing provider validates every captured source and admitted expansion record
through DiscoverySeal before reading the snapshot. Positive and negative queries
both depend on that certificate. No matcher, expansion execution, native helper,
query publication side effect or body preparation is added to a provider. Unknown
or unresolved producers cannot publish a seal or memoize a missing-name result.

and import identities, original textual imports without invocations, invalidation
of absence after source replacement, unresolved producer refusal, duplicate candidate
identity retention, raw spelling and cfg membership, and foreign scope refusal.
Generated negative queries also check the transitive admitted-record dependencies.

remains exercised.

Remaining M013 work includes dependency/definition-unit routing, complete contextual
selection/origin invalidation, generated-body runtime macro contexts, symbolic type
and alias paths, all quota/failure boundaries and full MX027/MX028 CLI fixtures.
