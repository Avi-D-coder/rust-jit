# M010 lexical attribute request admission

Original attribute input preparation retains private parse, item/meta range,
ordinal, owner, cfg and selection-identity provenance. Assembly refuses a changed
public identity and validates the live profile; retained provenance is counted in
the bounded request allowance.

`PreparedItemRequest::admit_original_attribute` polls the current lexical cursor
and requires the exact procedural definition selected by the original source
namespace. Request provenance must match the current meta, and worklist owner/cfg
must match that provenance. The existing worklist then verifies selection identity,
revision, kind, compile environment and epoch. Admission performs no helper call,
query adoption or effect. Namespace sealing and execution authority remain separate
requirements. Resolver-supplied generated worklists still use the lower-level
admission API; generated source binding remains later integration.

The actual original-item request fixture now exercises this path before the
authorized external-server call, record adoption and replacement reanalysis demand.
An unknown later attribute disappears when the first attribute replaces the item;
the resulting item agrees with native Rust 1.99.0. Wrong procedural definition,
later source meta, foreign parse, stale revision, repeated admission and a worklist
with different owner/cfg refuse without macro execution. Existing sibling derive
admission and native comparisons remain exercised.

This is explicit original-source request/worklist integration. Automatic query
orchestration, generated item reconstruction, namespace seals, full MX018–MX020,
M010 completion, project release and Linux acceptance remain pending.
