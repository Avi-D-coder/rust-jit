# M013 child macro worklist admission

M013 remains in progress. A staged physical module retains its immutable prepared
source lease and source macro index. Discovery's existing ResolveMacro worklist
now resolves its actual item calls. Ready calls return a retained NeedExpansion
request; polling replays the same Arc until external expansion/admission. Pending
preceding or annotated producers remain blocked. No macro executes during polling.

Admission requires the exact pending declarative key and an unsealed, unfailed
request. It validates GeneratedItems and the actual generated header/catalogue
plans, checks record uniqueness and generated wire/header/metadata quotas, and
preflights real job/member/dependency updates before namespace mutation. Source
bases and selected original owner order are retained. The record descriptor and
observed compiler input stamps become worklist dependencies. Partial namespace
application poisons discovery rather than allowing a seal.

Headers and imports enter the existing namespace graph. Completed generated
macro definitions publish into the retained child's textual source index, so a
later physical call can use a macro emitted by an earlier admitted expansion.
Generated body/context ownership is retained. A completed call closes its own
textual producer, and its shared source frontier only closes when every actual
call sharing it has completed. Completion counts distinguish resolved source
invocations from admitted records that still contain unresolved producers.

Unresolved generated calls/module demands retain their actual catalogues and
opaque worklist jobs. Such outputs do not complete the original textual producer,
and do not unblock later lookups through it. Unknown transformations refuse
before record or header admission and preserve the pending request. The outer
file-module frontier remains pending even after all currently handled calls:
source publication, complete imports/exports and module completion still need proof.

Four new controls cover exact pending reply/replay, substituted and duplicate
record refusal, actual later argument tokens, a generated definition used by the
next physical call, unresolved generated producer/catalogue retention, and
unknown-transform refusal without partial admission. Database revision and
publication remain unchanged while the module frontier is open. Source macro
index metadata now includes owned hygiene facts and is checked both at staging
and completed-binding admission; catalogue/index growth has bounded accounting.

Recursive generated-child request processing, nested file-module layout/context,
compiler macro routing from physical children, complete namespace import/export
integration, source/cache publication and final module-frontier closure remain
required. This checkpoint does not claim actual LRR child runtime/native equality,
full MX027/MX028, JIT, release or Linux acceptance. Historical positive module
native/LRR evidence remains pending. macOS ARM64 Rust 1.99.0 remains primary.
