# M013: generated replacing attribute reanalysis

Revision 4 Sections 50–51 and fixed Section 57 milestone C. macOS ARM64,
Rust 1.99.0 first. M013 and full release acceptance remain incomplete.

Invariant: replacing output is reanalysed as owned tokens and syntax before its
headers can publish. Generated attributes retain actual token origins, source
order, consumer scope and exact parent expansion identity. Remaining transformations
and derives/helpers keep membership incomplete; they are never guessed inert.

The pinned adapter selects a generated item and its effective attribute metadata
through the token-tree syntax map. It assembles item input with the applied
annotation removed and cfg filtering applied, retaining original token subtrees,
span/context records and remaining effective annotations. It selects actual argument
and path forests. No display-text reparse or fabricated source span is used. Attribute
counts, part allocations, retained token bytes and merged tables have checked bounds.

The generated worklist uses a typed function/attribute call index. A generated
attribute resolves the exact prepared export, verifies path context consistency,
and assembles the matched native request. The owning MacroRun's existing catalog,
key, authority, budget, adoption and final-input checks remain required. Original
transformed headers are withheld; returned outputs use the generated child worklist
recursively. Final completed selections replay before seal/publication.

Inflight attributes check all active child candidate routes for known ambiguity or
changed export identity. Candidate absence/pending cannot certify completeness.
This permits an exact ambiguity refusal even when the import worklist is blocked,
without executing another helper or closing an unresolved frontier.

Five actual-server controls exercise two replacing attributes; an attribute emitted
by a function-like macro; generated cfg_attr with an inactive panic macro; an actual
late conflicting attribute import; and the pinned chain_begin/chain_finish fixture
whose required derive/helper output remains incomplete after two native invocations.
Positive cases settle a declarative macro and import, remove discarded declarations,
and publish through the owning run. Negative cases cannot seal or publish. The
shared driver requires exact native/output counts and refuses pure/unadopted output.

Initial failures are preserved: pinned Meta token-tree API mismatch, typed call index
comparison/borrow adjustments, the previous fixture's single-call expectation, and
an inflight selection conflict hidden behind pending child imports. None are recorded
as passes. The architecture audit also caught a frontend reference to a service
helper; its unchanged stable producer encoding now belongs to the pure syntax model. Two older admission-refusal controls were updated to require retained tokens and
repeatable incomplete discovery for unknown generated attributes, with sealing
and publication still forbidden. The revised module control exposed an early source
request from an attributed external module. The generated header plan now withholds
that request until replacement output is adopted; the regression requires zero
unresolved module source requests while the unknown attribute stays pending.
The first full gate failure and focused regression failure are preserved.
Actual final results belong to the checkpoint.

Derive/helper registration, append behavior and complete transformation ordering,
all module/impl/trait/import and macro-definition attribute semantics, exact
world/edition/Cargo matrices, full CLI/service integration, M014–M016, broader
language/traits/JIT/native/security/performance, full fixture/release and Linux
