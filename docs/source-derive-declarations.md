# M010 captured source facets for derive helpers

The fixed architecture excludes rustc_driver and rustc metadata decoding. API6's
export list cannot supply helper names, but source-based macro facets are already
required by Section 55. `expand::derive_declaration` reads proc_macro_derive
arguments from owned pinned-AST token recipes. It validates the exported identifier
and helper list, canonicalizes raw/NFC names, deduplicates helpers, and checks
count/name/byte limits. Invalid paths, literals, metavariables and duplicate derive
annotations refuse. cfg_attr materialization uses the existing cfg frontend.
Unknown transforming attributes refuse until expansion is supplied. Bodies remain
cold and no source text is synthesized from macro display output.

`MacroSession::register_source_derive` admits an original declaration only from
its frozen preparation fingerprint, exact ProcMacroHost producer and captured
source path/content. The original-file path must equal Cargo's recorded source root and lie within the
producer's package root; producer cfg drives preprocessing. The declaration must name a derive
actually loaded from that exact artifact. The binding fingerprint covers the
preparation, producer, artifact and source/header/cfg facts. Conflicting records,
stale context/preparation, changed bytes and wrong units refuse. Registration is
idempotent and the registry has checked count/byte limits.

`derive_helpers` returns names from an admitted source facet. Without a facet,
protocol Unavailable remains distinct from empty helpers and returns the recorded
capability diagnostic. `derive_helper_binding` produces the exact identity-bound
record consumed by ItemHelperScope; it does not invoke a macro or grant authority.

The actual pinned preparation fixture compiles only proc dependencies while its
live consumer retains an undefined cold call. Registration reads MemberCfg and a
cfg_attr-produced raw-keyword export from that same captured source. Positive
helper lookup follows the resulting binding with zero session invocations.
Three native compiler observations accept first and r#type and reject a helper
not declared by the export. The source reader's duplicate/raw behavior agrees with
that compiler. Two unit checks cover conditional declaration visibility, harmless
body non-entry and malformed/unexpanded headers.

This establishes captured original-function declarations; [declared-edition metadata](source-derive-editions.md) also has original-source acceptance. Automatic
original-source catalog admission now has separate [catalog evidence](source-derive-catalog.md). It is
not a complete macro-host export catalog: declarations
generated by macro_rules/proc macros/includes, outside-root captured source,
full mixed-edition/generated facet integration and full source-aware reanalysis remain pending.
Their frontend/capture components are assigned to later M013–M016/M037/M038 tasks
in the fixed ledger order. Full MX018–MX020 and release helper acceptance remain
mandatory. No different server/frontend, private compiler dependency, native
symbol enumeration or compiler execution during live lookup was added.
