# M013 generated derive helper dispatch and receipt adoption

Revision 4 Sections 49–51 and Section 57 milestone C, macOS ARM64, Rust 1.99.0.
M013 remains in progress. The invariant is that helper metadata resumes its exact
producer without completing it, executing a derive, or publishing a seal.

The generated catalog returns a typed NeedDeclaration for each selected derive
in lexical order. The discovery scheduler retains its active ticket and request;
repeated polling returns that same request. The authorized MacroRun coordinator
uses the existing matched-session source-facet worker to obtain an immutable
receipt. That pure data type lives in the expansion layer; source capture remains
in the service layer and never runs inside a frontend query.

Coordinator adoption requires the exact pending request, matching receipt,
database epoch and adopted parent descriptor. It rejects changed captured compiler
inputs, absent child catalogs, duplicates and checked metadata limits. Both the
catalog insertion and worklist dependency are preflighted before mutation. Receipt
fingerprints bind stable explicit fields; metadata retention has a checked 32 MiB
limit. Adoption records that immutable dependency and retries the same producer.
It grants no namespace completion or wakeup of unrelated producers.

After both declarations are ready, discovery still reports the first derive
occurrence as pending: helper classification and ordered execution are not yet
implemented. An explicit deferral operation lets pending controls retain their
incomplete outcome. Deferring is not a fixture pass, execution or seal admission.

The matched-server acceptance chain dispatches CheckDeriveInput and Empty,
adopts their exact declarations in order, and rejects a different receipt and
duplicate adoption. It retains two attribute invocations, no derive invocation,
no seal and no publication. The worklist regression checks that retry does not
complete the producer, refuses a changed immutable fingerprint without mutation,
and leaves blocked discovery incomplete. Final gate counts and proof hashes are
recorded in the checkpoint, rather than inferred from test registration.
