# M010 source-selected item requests

`service::item_macro_requests::PreparedItemRequest` joins original attribute/derive
input preparation to the frozen procedural session and item transformation
worklist. The source-aware resolver supplies the exact artifact/export and owned
site registry. The assembler creates item-grammar requests, retains attribute
argument contents, and carries only missing selected site spans and their context
ancestors into the preprocessed item forest. Removed annotation spans therefore
remain available to the external protocol without restoring annotation tokens.
No source printing, ambient reads, macro execution or query publication occurs.
Positive targets in the integrated acceptance now resolve through the existing
source namespace graph and [prepared procedural catalog](prepared-procedural-namespace.md)
before request assembly, preserving exact artifact/export/form identities.

Each derive occurrence has a stable selection identity including the owning input,
ordinal, source path spelling and endpoint spans. Repeated paths have independent
invocations. Prepared requests admit only the currently suspended worklist slot
with the same selection identity, index, revision and macro form. The frozen
session validates exact loaded exports and producer/consumer context before the
worklist receives the key. Request fields are private after construction.

Retained input admission checks token allocations, argument allocations, source
table capacity, shared captured text/path storage, export capacity and request
metadata against 64 MiB using checked arithmetic. Site context traversal is bounded
and validates owned schema records; absent site proof cannot fabricate a span.

The actual macOS acceptance prepares only controlled macro tools with the pinned
Cargo planner. Its deliberately invalid live consumer is never compiled. Original
attribute replacement and member-filtered derive inputs pass through prepared
requests, worklist admission, query suspension, external service execution,
immutable database adoption and coordinator transform admission. Two native
Rust 1.99.0 oracles compile and run; the observed replacement name and derive
member string agree with actual expansion tokens. Repeated empty derives execute
separately. Missing sites/exports, stale contexts/revisions, foreign selection
identities, repeated admission and excessive retained capacity refuse. No rejected
request executes a macro. A reply cannot advance the worklist before adoption.

Automatic source lookup/classification, generated-token reanalysis, whole-file
publication/discovery and guest execution remain pending. Builtin/helper inert
decisions still require resolver certification. This component does not complete
MX018–MX020, M010, release acceptance or the later Linux port.
